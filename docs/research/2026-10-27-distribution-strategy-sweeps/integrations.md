## 1. Workflow, automation and agent platforms

What "real, not hollow" means on every platform: the integration is built from the platform's own primitives (the node, piece or component SDK, its auth object and its test harness). It exposes typed operations for named jobs, such as "Verify company (registry)", "Validate EU VAT" and "Screen sanctions/PEP", instead of a single free-form JSON "execute slug" box. It ships a test that runs on the platform's own harness.

### 1b. Recurring jobs a Strale step can own on these platforms
- **New vendor or supplier added** (form, sheet row, ERP webhook) → registry lookup, VAT check and sanctions screen → write the result back and alert on a miss. This is triggered per supplier.
- **Each inbound invoice** (email parser or AP inbox) → VIES VAT check plus IBAN format check, the "invoice verify" bundle. This is triggered per invoice and is the highest-frequency job.
- **Monthly re-screening** (n8n Cron, Zapier Schedule, Make scheduler) → loop over the counterparty list → sanctions/PEP re-check. This is a calendar-driven recurring job, and the clearest way to turn one-off use into recurring use.
- **CRM company created** → enrich with official registry data.
Strale **triggers** would raise stickiness further, but the API has no event source. Schedule-based polling by the platform covers the re-screening case.
