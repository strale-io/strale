## Decision

While drafting landing-page Section 6 (Coverage), the row found the
planned copy ("No scraping. Every underlying call runs against a direct API
or a licensed redistribution contract.") false against production: the
Payee Assurance canonical page's own scope-reality-check documented 9 of
17 covered EU countries relying on Browserless + LLM scraping (BE, ES, IE,
IT, LT, LV, NL, PT, SE), plus Germany via the northdata.com aggregator.
Rather than soften the copy, the row commits to fixing the implementation:
every scraping country must migrate to a direct government-registry API or
a licensed commercial aggregator before v1 launch, adding "a P0 sweep for
the complete 9-country resolution."

## Context

The row's own text states this is "consistent with Brand & Voice 4.1
(data-source-type doctrine under DEC-20260420-I)." **`DEC-20260420-I` is
this same batch's other collision.** "Data-source-type doctrine" is an
exact match to the subject of
`DEC-20260420-I--notion-34867c87082c81c8b9d4c6b5568bbcef` (the row this

target a relation for that unnamed reference.

This historical ID is reused by a second, unrelated Notion row (replacing

The historical Notion scope field on this row was `global`. It is recorded

commitment.

## Rationale

The rationale, as the row states it: shipping "No scraping" copy while
production quietly scrapes 9 jurisdictions would make the positioning
false, and softening the claim "weakens differentiation" against
"the x402 MCP wrapper crowd," so the row chooses to fix the implementation
rather than the copy.

## Consequences

Status verified on 2026-09-05, against `main`.

**Some scraping-based `data_source_type` values remain in the manifests
today, but the doctrine's own category names never shipped, so this row's
"migrated to a direct API or a licensed aggregator" cannot be verified
country-by-country against the row's original 9-country list.**
`manifests/*.yaml`'s `data_source_type` values today are `api` (224 + 1),
`computed` (81), `scrape` (32), `reference` (3), and `ai_assisted` (1); 32
capabilities still declare `scrape`. This record did not enumerate which of
those 32 correspond to the nine countries this row names (BE, ES, IE, IT,
LT, LV, NL, PT, SE) or to Germany's northdata dependency, so it cannot
confirm the specific 9-country migration this row committed to, only that
literal scraping (`data_source_type: scrape`) has not been eliminated from
the catalog as a category.

**`DEC-20260428-A`** (existing record, "Adopt a three-tier doctrine for
third-party scraping") and **`DEC-20260813-A`** (existing record, "Affirm
constrained per-call parsing as the scraping doctrine interpretation")
together establish a later, more permissive framework than this row's
absolute "must be migrated" commitment: `DEC-20260813-A` affirms that
"per-call parsing" of statutorily-public registry pages, under four named
constraints, is a legitimate reading of the underlying doctrine rather than
a violation requiring migration. Whether any of the 32 `scrape`-declared
capabilities today operate under that later, narrower permission (rather
than being residue this row's P0 sweep failed to close) is not
distinguishable from manifest data alone.

## Reversal conditions

None recorded on the row (`Superseded By` and `Outcome` are both null). If
