## Decision

Keep Implisense in the Vendor Roster as Backup, not Active or Rejected: set
up a RapidAPI free Basic account, and use it only as a complementary route
for Strale customers who explicitly require guaranteed-fresh live registry
data and are willing to bear the per-call cost via customer-funded
passthrough. Do not pay for the Pro or Ultra tiers preemptively.

## Context

Implisense CPO André Bergholz replied 2026-05-05, confirming the
embed-and-bill model is supported via RapidAPI, but stating a hard
constraint: caching is not permitted on any channel, quoted as "each call
to your customers needs to correspond to a live API call on our end."
This is recorded as incompatible with Strale's primary v1 stored-with-refresh
architecture, per `DEC-20260505-H` selecting OpenRegister as primary.

Three structural issues justify Backup placement rather than Active or
Rejected: (1) hard tier limits on Basic/Pro create customer-facing
reliability failure modes when the limit is hit; (2) no-caching means no
compounding economics from repeat lookups across Strale's customer
portfolio, since OpenRegister serves cached facts for free while Implisense
charges every time; (3) an 8x cost step from Pro (USD 39.95) to Ultra
(USD 339.95) with no mid-tier creates a pricing cliff at the volume where
Implisense would matter. Despite this, per-call costs are recorded as
roughly 3x cheaper than OpenRegister at Pro tier (USD 0.16 versus EUR
0.54), so the row explicitly corrects an earlier "unit economics murdered"
framing as wrong: the architectural incompatibility, not cost-of-goods, is
the real issue.

Three reasons are recorded for keeping the relationship despite Backup
placement: (a) fallback if the OpenRegister audit-retention negotiation
fails; (b) potential field coverage outside OpenRegister's core; (c) the
preserved relationship with the CPO is cheap to maintain.

The historical Notion scope field on this row was `global` in the
workspace's old vocabulary. It is recorded here as `scope: technical`
under this repository's decision-record vocabulary: this is a vendor-tier
placement choice within one capability family's sourcing.

## Rationale

The rationale is the caching-clause incompatibility with Strale's
stored-with-refresh architecture, weighed against Implisense's lower
per-call cost and useful complementary field coverage: the architectural
mismatch, not price, is what keeps Implisense at Backup rather than Active.

## Consequences

Status verified on 2026-09-04, against `main`.

**Implisense has no live code anchor.** `apps/api/src/capabilities/german-company-data.ts`
is the only capability sourced from a German-registry vendor and it fetches
exclusively from OpenRegister (`https://api.openregister.de`); no
`implisense` reference exists anywhere under `apps/api/src`. `config/env-manifest.yaml`
has no Implisense-named row (no API key, no RapidAPI credential). The Basic
RapidAPI account this row commits to setting up is not evidenced anywhere
in this repository. This row's positioning claim, that Implisense is kept
as a complementary Backup route, has no live anchor: the code implements
only the Active vendor (OpenRegister), and the Backup relationship this row
describes is not wired to any executor or credential on `main`.

**The readiness program retired Counterparty Assurance as the primary
product.** `DEC-20260812-A` (`docs/decisions/records/DEC-20260812-A.md`,
CLAUDE.md's "Current Decisions (August 2026)" paragraph) retired the
Counterparty Assurance framing this row's German-registry vendor sourcing
served, stating "compliance is a separate track gated on customer
discovery." This row's vendor-tier placement mechanism (OpenRegister
Active, Implisense Backup) survives only as far as `german-company-data`
itself survives as a live capability; the row's own Backup-tier commitment
to Implisense specifically has not been executed in code.

## Reversal conditions

Reconsider this row if the OpenRegister audit-retention negotiation fails
(the row's own stated reason (a) for keeping the relationship), or if a
customer need for guaranteed-fresh live data at Implisense's stated
per-call rate materializes; either would be the trigger to actually wire
the RapidAPI Basic account this row committed to setting up but which is
not present in code today.
