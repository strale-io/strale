## Decision

Replace a planned 7-day traffic soak (gating Phase 4 on real onboarding
traffic exposure to surface latent bugs) with four evidence-based gates
executed the same day: Railway deploy health; a real-path upsert through
`persistCapability` against a live capability; a deliberate hook failure to
exercise the `hook_failed` path; and a regression scan for unexpected
`hook_failed` rows.

## Rationale

The rationale, as the row states it: a soak period is only useful when
real traffic exercises the changed code path; with effectively zero
onboarding traffic, replacing a calendar-based wait with gates that
directly exercise the code (deploy health, a real upsert, a deliberate
failure, a regression scan) produces actual signal instead of a
time-elapsed illusion of one.
