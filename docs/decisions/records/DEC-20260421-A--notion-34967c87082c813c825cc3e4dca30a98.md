## Decision

Commit the sandbox and product input surface to a single field, company
name only, starting from the founder's ambition that "ideally the only
input needed would be Spotify AB." The row's own estimate: single-field
resolution is realistic for "~70-80% of real inputs" with a jurisdictional
marker or global uniqueness; the remaining 15-25% require disambiguation
candidates; the last 5-10% require asking for more input. This promotes
entity resolution "from 'priority' to 'v1 launch blocker'."

## Context

The row states downstream operational impact: the Payee Assurance product
page's input spec updates from "name, country, any identifiers" to
"company name required; identifiers optional; jurisdiction inferred." The
sandbox ships with "six deterministic presets (Spotify AB default,
cross-border, Wagner, dormant, mismatched IBAN, small DE GmbH)" and "a
disambiguation response pattern for custom inputs." The row also states the
launch timeline "now depends on three parallel tracks: website rebuild,

## Rationale

The rationale, as the row states it: publicly committing to a single input
field on the landing sandbox "leads the product input shape" and forces
entity resolution to land by launch rather than remaining an open-ended
priority; the 70-80%/15-25%/5-10% split gives a concrete target for what
"realistic" single-field resolution means rather than an unbounded
ambition.

## Consequences

Status verified on 2026-09-05, against `main`.

**No dedicated "entity resolution engine" capability or matching feature
by that name is present in this repository.** A search of
`apps/api/src` finds no module named for entity resolution or company-name
disambiguation as a distinct capability; company-data capabilities under
`manifests/*.yaml` generally require a structured identifier (registry
code, VAT number, or similar) alongside or instead of a bare company name,
which is a narrower input contract than this row's "company name only"
target. This record does not confirm whether the single-field sandbox
input this row describes shipped on the current production site, since
that would require reading `strale-frontend`'s sandbox component, out of
scope for this pass.
