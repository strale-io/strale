## Decision

The record-key grammar gains a second source qualifier, symmetric to the
existing `--notion-<32 hex page id>`: `--git-<7 to 40 lowercase hex>`, naming
the commit that introduced the claim directly in Git. The pattern, verbatim,
in every place the previous pattern appeared:

```
^DEC-[A-Za-z0-9]+(?:-[A-Za-z0-9]+)*(?:--notion-[0-9a-f]{32}|--git-[0-9a-f]{7,40})?$
```

A record whose key matches `--git-<sha>` must: have `id` equal to the key
with the qualifier removed; be listed in `formal_records` with
`source_kind: git-native`, `source_rows: []`, and `git_provenance` equal to
the record's own first evidence entry, which must be
`https://github.com/strale-io/strale/commit/<full 40-hex sha>` whose prefix
is `<sha>`; and name a commit that is an ancestor of HEAD. When git is
unavailable the ancestry check is warning-class (`COMMIT_UNVERIFIABLE`), not
a pass. A record failing any of the first three checks is
`RECORD_GIT_KEY_ID_MISMATCH`, `RECORD_GIT_KEY_SOURCE_KIND`, or
`RECORD_GIT_KEY_PROVENANCE_MISMATCH`; failing ancestry is
`RECORD_GIT_KEY_NOT_ANCESTOR`.

A bare collided id is never a record key. This already held for
notion-duplicate collisions in `id-collisions.yaml`; it now also holds for a
cross-surface collision id recorded in the M2 closure register
(`RECORD_KEY_BARE_CROSS_SURFACE_ID`).

A cross-surface collision row (`collision.kind: cross-surface`) may resolve
to `disposition: resolved_collision` with `collision.resolution_status:
resolved` and `collision.row_disposition: documented_only` if and only if a
git-qualified record exists whose id equals the collision id, and the row's
page id is named by a tracked gap report that the row itself cites in
`evidence`. `row_disposition: formal_record` is refused on a cross-surface
row in this stage (`CROSS_SURFACE_FORMAL_RECORD_UNSUPPORTED`); it may be
specified by a later batch. `unresolved`/`unresolved` remains valid in every
case; any other resolution_status/row_disposition combination is
`DECISION_ROW_CROSS_SURFACE_STATE_INVALID`. The disposition-derivation rule
follows the same test: a row claimed by a Git-native label is expected
`resolved_collision` exactly when both conditions hold, otherwise
`unresolved_collision`.

`record_key` relation and formal-record targets may be git-qualified the
same way they may already be notion-qualified; the bare id stays
untargetable either way.

A `--git-` qualified key's legitimacy is not gated on the notion-duplicate
collision registry (`id-collisions.yaml`, which by design never carries a
cross-surface id): `validateDecisionRecords` accepts a `--git-` key without
consulting that registry, `--notion-` keys keep the registry-bound rule
unchanged, and the closure register's own validator (`RECORD_GIT_KEY_*`
above) is the one that requires a git-qualified record's id to be claimed as
a cross-surface collision (`collision.kind: cross-surface`), refusing an
unclaimed git-qualified key as `RECORD_GIT_KEY_WITHOUT_CROSS_SURFACE`: a
plain git-native decision whose id is not a cross-surface collision, such as
`DEC-20260504-A`, keeps a bare key.

## Context

G3 in `docs/project/m2-closure-register.yaml` names a gap the existing
mechanism cannot close: `DEC-20260422-A` is one active Notion row (Phase
4b.2 orphan-resolution execution record) and, separately, the id under which
commit `3b25658736bfed53eec52c8acf2619dacd54d1f5` introduced the Distribution
PR Integrity Protocol directly in `CLAUDE.md` and `AGENTS.md`. The
Notion-only collision registry (`id-collisions.yaml`) is generated from
duplicate Notion source rows and structurally cannot represent a Notion row
colliding with a Git-native authority claim; the register therefore holds
this row as `unresolved_collision` with `collision.kind: cross-surface`, and
the validator refused any other state for such a row. Full analysis:
`archive/sessions/2026-09-01-m2-enforcement-protocol-source-gaps.md`.

## Rationale

Symmetry with the existing `--notion-` qualifier keeps one grammar for
"where did this id's authority come from" rather than inventing a second
mechanism. Binding provenance to an ancestor commit, rather than trusting a
free-text claim, makes the assertion checkable the same way Notion
provenance already is. No cross-surface collision's meaning is chosen
silently: the bare id stays untargetable, and a row may only resolve when
both a qualified record and an evidence citation exist together.

## Consequences

This batch lands and verifies the mechanism only; it creates no
`DEC-20260422-A.md` record in either meaning, and does not change the
`DEC-20260422-A` row's collision payload or disposition. A later,
independently reviewed batch (stage 2, per `docs/decisions/README.md`'s
two-stage resolution rule) applies the mechanism to that specific collision:
two distinct qualified records, or an evidence-only disposition for one or
both meanings. The mechanism itself is general and available to any future
cross-surface collision the audit finds.

## Reversal conditions

Supersede this decision if a different cross-surface identity mechanism is
adopted, or if the `--git-` qualifier proves unable to represent a real
provenance claim the audit encounters. An extension of the mechanism (a new
finding code, a new resolution path) that preserves this grammar and these
invariants does not require supersession.
