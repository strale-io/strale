## Consequences

Status verified on 2026-09-05, against `main`. The three named
capabilities exist; the 60 named solutions do not appear in the current
canonical solution source.

**The three capabilities exist today.** `manifests/pep-check.yaml`,
`manifests/adverse-media-check.yaml`, and
`manifests/risk-narrative-generate.yaml` are all present on `main`,
matching the row's three named capabilities. CLAUDE.md's "New
capabilities (March 2026)" section independently lists all three with
descriptions consistent with the row.

**The repository's current canonical solution definitions contain none
of the 60 named solutions.** `apps/api/src/db/solution-catalogue.ts`
(its own header states it was "split out of seed-solutions.ts on
2026-08-16 so the definitions can be imported, validated and tested"
and is the sole source `seed-solutions.ts` upserts from today) declares
zero entries whose `slug` matches `kyb-essentials-*`, `kyb-complete-*`,
or `invoice-verify-*`; `git log -S"kyb-essentials"` against both files
returns no commit, meaning that literal string was never added to or
removed from either file in this repository's history. The 60 solutions
this row describes were written by a separate, one-off script,
`apps/api/scripts/seed-kyb-solutions.ts` ("Seed 60 new solutions (KYB
Essentials, KYB Complete, Invoice Verify) across 20 countries, and
deprecate 5 old solutions"), whose slugs are built by template
(`` `kyb-essentials-${c.code}` ``, `` `kyb-complete-${c.code}` ``,
`` `invoice-verify-${c.code}` ``) rather than declared statically, so
they were never captured when the catalogue was split out.

**Two later retirement scripts confirm at least part of the family was
built and then deliberately deactivated, not merely undeclared.**
`apps/api/scripts/archive/drop-aggregator-kyb.ts` soft-deactivates 15
solutions (`kyb-essentials-{nl,pt,es,de,at}`,
`kyb-complete-{nl,pt,es,de,at}`, `invoice-verify-{nl,pt,es,de,at}`) per
its own header, citing the commercial-KYB-aggregator scraping ban
(DEC-20260427-I); `apps/api/scripts/archive/drop-sg-kyb.ts`
soft-deactivates 3 more (`invoice-verify-sg`, `kyb-complete-sg`,
`kyb-essentials-sg`) for a structural no-viable-data-source reason. That
accounts for 18 of the row's 60 as later `is_active = false` in the
database, leaving 42 of the row's original solutions unaccounted for in
any file this repository can read.

**What this repository can and cannot prove about the database:** it
can prove the seeding script existed, was designed to write exactly the
row's claimed 60 rows on a template pattern matching the row's naming,
and that a subsequent 18 of those rows were deliberately deactivated by
separate scripts naming this row's product family by name. It cannot
prove, from source alone, whether the seeding script was ever run
against production, whether the remaining 42 rows are still `is_active`
in the database today, or whether the country coverage still matches
"20 countries." CLAUDE.md's own "New solutions (March 2026)" section
still lists the family with its per-country slug pattern and country
list, unchanged since authored, which this record does not treat as
independent confirmation of current database state.
