## Decision

Claude Code self-merges feature-branch PRs after its own session-end
verification passes, when CI is SUCCESS and no carve-out applies.

## Context

The row's Rationale states: "CC has full gh CLI auth (it opens the PRs) so it can also close them. Solo-founder context means no separate reviewer in the loop — self-merge after CC's own session-end verification is safe. Three sessions on 2026-05-06–07 produced PRs that sat unmerged for hours because chat was defaulting to manual-merge UI; this rule structurally enforces the autonomous-merge workflow when its trigger conditions are met (CC produced the PR, session reached closing steps successfully, CI is SUCCESS, no carve-out applies)."

## Rationale

The rule closes a concrete operational gap: PRs sitting unmerged for hours
because the default flow required a manual step no one performed in a
solo-founder, no-second-reviewer context.

## Consequences

Status on 2026-09-05, verified in files: `CLAUDE.md` states "**Shipping is never Petter's decision** — the session that opens a PR merges it and reports afterwards in plain English;" under DEC-20260815-A, which is the
same self-merge posture this row establishes, now carried at the operating
charter level rather than as a numbered closing-steps rule. `CLAUDE.md`'s
session contract requires the handoff gate to pass and the branch to be
pushed before a session ends, consistent with the self-merge-after-
verification posture this row established in 2026-05.

## Reversal conditions

Supersede this decision if a carve-out condition becomes the norm rather
than the exception (for example, if CI SUCCESS stops being a reliable
signal), or if the operating model reintroduces a mandatory second reviewer.
