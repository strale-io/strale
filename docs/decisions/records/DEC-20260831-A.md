## Decision

Strale will adopt the staged repo-native operating model defined by the agreed
migration plan. Codex and Claude Code will use peer entrypoints over one shared
canonical project layer. Notion will be retired as an active authority and
workflow dependency only at the plan's atomic cutover milestone, after its
content and consumers have been preserved and replaced.

## Context

Project truth, current state, decisions, design work, and operating history have
accumulated across Notion, tool-specific instruction files, chat summaries,
handoffs, multiple repositories, and local untracked directories. The existing
model makes `CLAUDE.md` canonical and `AGENTS.md` derivative, which creates
asymmetry and drift between Claude Code and Codex.

The founder requested a shared, persistent repo-native system and explicitly
approved creating, independently reviewing, storing, and orchestrating the
migration plan. A collision check against the exported Decisions database and
the repository found no existing `DEC-20260831-A`.

## Rationale

A small canonical layer with one authority per question is easier to load,
review, version, and mechanically validate than either a single project bible
or multiple mirrored memory systems. Staging preservation, foundation,
reconciliation, replacement, cutover, and archival separately keeps evidence
recoverable and avoids a period of dual authority.

## Consequences

- The migration plan is the execution authority for this operating-model work.
- Imported context, Notion content, handoffs, and audit reports remain evidence
  until reconciled; importing them does not promote their claims.
- Existing entrypoints and Notion workflows remain active until M4; there is no
  dual-write transition.
- Every critical milestone receives independent Claude Code verification.
- Product truth is populated only after the separate product/decision audit is
  available and reconciled in M2.

## Reversal conditions

Supersede this decision if clean-session acceptance demonstrates that the
repo-native model cannot preserve required context or safety protocols within
the enforced startup budget, or if verified workflow replacements cannot meet
the operational requirements currently served by Notion.
