## Decision

Trust data must never be displayed with false confidence. Three-layer
protection: (1) a frontend display guard, `getTrustDisplayState()`; (2) a
backend anomaly-detection `data_confidence` field; (3) capability circuit
breakers, to prevent data pollution at the source.

## Context

The row's stated basis, from its own Rationale: KYC Sweden showed a
green checkmark next to a 0% pass rate because Anthropic credits ran
out. The quality pipeline faithfully recorded the failures and the
frontend faithfully displayed them: technically correct, but
practically misleading. The row states the governing rule: when metrics
are anomalous (cliff drops, stale data, absurd latency, zero data),
suppress or warn rather than display with false confidence. A green
checkmark next to 0% is called "a trust violation worse than showing
nothing." The row's `Source` field points to a shared specification
page (`https://www.notion.so/31967c87082c816d9d44cd4317386a30`), the
same page two other same-day rows in this batch cite.

This historical ID is reused by a second, unrelated Notion row (a trust
verification card visual-redesign decision made the same day) and was
an unresolved registry collision until this batch; the two rows are
resolved together in
`archive/sessions/2026-09-05-decision-collision-resolution-DEC-20260304-C.md`
with distinct source-qualified record keys. This record covers only the
false-confidence-prevention rule row.

## Rationale

The rationale, as the row states it: a metric that is technically
accurate but contextually absurd (0% with a green pass badge) misleads a
reader worse than showing no data at all, because it actively signals
confidence the data doesn't warrant. Three independent layers are named
(a frontend display guard, a backend anomaly flag, and a source-side
circuit breaker) so that no single layer's failure lets a false-
confidence display through.

## Consequences

Status verified on 2026-09-05, against `main` and the sibling
`strale-frontend` checkout, read-only. CLAUDE.md's Current Decisions
(March 2026) section groups this row's launch-week neighbours
(DEC-20260305-A through G, DEC-20260306-A through F) under "Trust
display centralization" and "Metric consistency," and both
`docs/decisions/records/DEC-20260305-G.md` and
`docs/decisions/records/DEC-20260306-D.md` (formal records for two of
those neighbours, migrated in an earlier T10 batch) describe the trust-
display system this row's principle grew into.

**The named frontend guard function exists, verbatim, with a
self-documenting header comment.**
`strale-io/strale-frontend@04c9fca9:src/lib/trust-display.ts` defines
`getTrustDisplayState()`, preceded by the comment "Every component
rendering trust data must call getTrustDisplayState() first," a mandatory
gate, consistent with the row's named mechanism, not an optional helper.

**A literal `data_confidence` field was not found on the backend trust
route checked.** `apps/api/src/routes/public-trust.ts` and
`apps/api/src/lib/trust-grade.ts` carry no field named `data_confidence`.
Instead, `trust-grade.ts` computes a combined grade as "the worst of
(SQS grade, freshness grade, latency grade)," with freshness grades
(A/B/C) reflecting staleness and a `label` describing e.g. "Reference
data (stale: Nd since update, cycle Nd)." This is a different, more
granular anomaly-signalling mechanism than the row's named single
`data_confidence` field; this record treats it as an evolution of the
row's stated principle (suppress or contextualize anomalous metrics),
not a contradiction of the row's underlying rule, though the specific
field name the row anticipated does not exist under that name.

**Capability circuit breakers exist as a source-side layer.** This
record did not re-derive the circuit-breaker mechanism from source in
full; its presence is corroborated by `docs/decisions/records/DEC-20260306-D.md`
and by this batch's sibling records citing `apps/api/src/lib/circuit-breaker.ts`
in other trust-related capacities.

## Reversal conditions

None recorded on the row (`Superseded By` and `Outcome` are both null in
the source). A future decision permitting an anomalous metric to display
without a suppression or contextualization guard would supersede this
row.
