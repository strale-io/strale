## Decision

Major pivot: from a competitive-intelligence (CI) product to a commerce
protocol. Strale is the MCP server for agent-to-agent transactions. The
product is an MCP server plus SDK enabling agent-to-agent transactions:
transaction protocol, registry, matching, escrow, and verification and
reputation are to be built; CI reports, PDF engines, domain-specific
pipelines, and enterprise sales are explicitly not to be built.
Go-to-market: the MCP developer community, an open-source SDK, and
wrapped public APIs as seed supply.

## Context

The row's stated basis, from the row's own Rationale: after building
full-spec CI prototypes (named: ICE Beauty, Gilion, Nordic HR-tech, Design
System Tooling), the team discovered that (1) CI reports tell insiders
what they already know, (2) building consulting-grade CI amounts to
building a separate company, (3) the CI product had drifted far from the
marketplace vision. The row's own Source field is null, unlike most rows
in this batch, which cite the shared strategy page.

This row `amends` `DEC-20260224-P-c3d4` (the prior day's "first vertical:
market research and competitive intelligence" decision): this row's own
text states the CI product "drifted far from marketplace vision" and
lists "CI reports" among what will not be built, directly reversing
`DEC-20260224-P-c3d4`'s choice of vertical. See
`DEC-20260224-P-c3d4` for the full text of the vertical this row
replaces.

The historical Notion scope field on this row was `global` in the
workspace's old vocabulary. It is recorded here as `scope: product`: this
is a foundational product-direction pivot, not a single technical
integration.

## Rationale

The rationale, as the row states it: hands-on prototyping across four
named full-spec CI builds surfaced that CI reports mostly restate what an
informed buyer already knows, that matching consulting-grade CI quality
requires building what amounts to a separate consulting business, and that
the CI direction had drifted away from the originally intended marketplace
vision; the row's chosen replacement (an MCP server and SDK for
agent-to-agent commerce) is judged closer to that marketplace vision and
buildable by a solo founder using wrapped public APIs as seed supply.

## Consequences

Status verified on 2026-09-04, against `main`.

**An MCP server for the platform exists on `main` today, matching this
row's core technical proposal, but it is not the platform's stated
primary commerce mechanism.** `packages/mcp-server/` exists (README,
`server.json`, `src/`), matching this row's "MCP server + SDK" build item.
However, `DEC-20260812-A` (`docs/decisions/records/DEC-20260812-A.md`)
states the current primary rail is x402, not the MCP server per se: "x402
primary rail" is explicit in that record's evidence trail via CLAUDE.md's
"Readiness program adopted" line, and CLAUDE.md's own "x402 Payment
Gateway (March 2026)" paragraph describes agent payment via USDC on Base
mainnet with "no signup or API key needed — payment IS the auth," which is
a different transaction mechanism from the MCP-server-mediated
registry/matching/escrow/reputation system this row specifies.
`docs/decisions/records/DEC-20260416-A.md` (cited in this batch's brief as
covering "strale-mcp vs x402") is the record most directly bearing on how
the two mechanisms relate; see it for the fuller reconciliation.

**"Escrow" and a reputation system, as this row specifies them, were not
found built.** No escrow mechanism or agent-facing reputation system was
found on `main` in this verification; the platform's trust mechanism today
is the quality floor (`DEC-20260812-A`'s quarantine/deactivation
thresholds on real-traffic quality signals), which scores capabilities,
not counterparty agents, and is a different mechanism from the
transaction-level escrow and reputation this row specifies.

**Stripe Connect, which an escrow-based marketplace would plausibly need,
is explicitly absent.** CLAUDE.md's Tech Stack states "Payments: Stripe
Checkout (wallet top-ups only, no Connect)," consistent with the
escrow/registry/matching machinery this row specifies never having been
built in that form.

**What survived, in substance: the framing of Strale as protocol/API
infrastructure for agents, rather than a human-facing report product.**
Both the "not CI reports" clause and the "MCP server + SDK" clause are
reflected in what exists today (`packages/mcp-server/`, the SDK packages
CLAUDE.md's Project Structure lists), even though the specific
transaction-protocol design (registry, matching, escrow, reputation) this
row lays out was not built as specified; the x402 rail
(`DEC-20260812-A`) is the mechanism that actually shipped for
agent-to-agent payment.
