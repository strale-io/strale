## Decision

Kill the "Compare with DIY" cost-calculator feature. Remove
`component_sum_cents` from the `SuggestRecommendation` interface.

## Context

The row's stated basis, from its own Rationale: the proposed feature
would have shown "Components individually: €1.10. Solution: €1.50 with
orchestration," literally advertising Strale's own markup. The correct
value comparison is "€1.50 vs 2 weeks of integration work" (the real
alternative a buyer faces), not "€1.50 vs €1.10" (Strale's own component
sum). The row's `Source` field points to a shared specification page
(`https://www.notion.so/31967c87082c816d9d44cd4317386a30`), the same
page two other same-day rows in this batch (the "hide component prices"
and "trust data must never be displayed with false confidence" rows)
cite as their source. The row also states this is consistent with an
earlier Discovery & Navigation spec rule: "never show component sum."

This historical ID is reused by a second, unrelated Notion row (a
stats-bar wording-swap decision made the same day) and was an unresolved
registry collision until this batch; the two rows are resolved together
in
`archive/sessions/2026-09-05-decision-collision-resolution-DEC-20260304-B.md`
with distinct source-qualified record keys. This record covers only the
"kill DIY calculator" row.

## Rationale

The rationale, as the row states it: comparing a solution's price to
its own component sum invites the wrong comparison (Strale's markup)
instead of the right one (the buyer's real alternative of doing the
integration work themselves); the calculator feature was never built
for this reason, and the underlying field it would have needed
(`component_sum_cents` on the suggestion interface) is removed with it.

## Consequences

Status verified on 2026-09-05, against the sibling `strale-frontend`
checkout, read-only.

**No "Compare with DIY" calculator component exists.** A grep for
`calculator`, `Calculator`, and `Compare with DIY` across the frontend
`src/` tree returns no matches; the feature was never built, consistent
with the row's directive to kill it before shipping.

**`SuggestRecommendation` (`POST /v1/suggest`'s per-item shape) carries
no `component_sum_cents` field**, in
`strale-io/strale-frontend@04c9fca9:src/types/index.ts`, matching the
row's specific instruction to remove it from that interface.

**A `component_sum_cents` field exists on a different interface,
`SolutionDetail`** (the shape for `GET /v1/solutions/:slug`), in both
`src/types/index.ts` and the raw-shape normalizer in `src/lib/api.ts`,
but is not rendered on any page this record checked. This is the same
distinct-surface field noted in the sibling "hide component prices"
record for this same collision date
(`docs/decisions/records/DEC-20260304-A--notion-31967c87082c8185b0a6c33de2293215.md`);
it is not the `SuggestRecommendation` field this row specifically named
for removal, so it is not treated as a contradiction of this row.

## Reversal conditions

None recorded on the row (`Superseded By` and `Outcome` are both null in
the source). A future decision reintroducing a DIY-comparison calculator
or a component-sum field on the suggestion response would supersede
this row.
