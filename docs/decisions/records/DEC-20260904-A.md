## Decision

Every preserved M2 closure-register Decision row that matches the predicate
below is classified `intentionally_historical` (evidence-only) in
`docs/project/m2-closure-register.yaml`, rather than pending migration to a
formal candidate record:

```
historical_status == active
AND historical_scope == feature
AND decided_at < 2026-08-12
AND disposition == not_yet_reconciled
AND NOT (page id or id in the collision registry, docs/decisions/id-collisions.yaml)
AND NOT (id is a Git-native protocol label, scripts/m2-closure-register-lib.mjs gitNativeClaims)
AND NOT (id is an existing formal record id, docs/decisions/records/*.md)
```

Applying the predicate against the private preservation archive at commit
`995cece3fe4abfb8b0bef0cccbd58191a6dab83c` matched 76 rows out of 216 private
rows (129 not-`not_yet_reconciled`-eligible rows and 11 non-feature or
inactive rows excluded; see the measured population in the gap report cited
above). The rows are listed by public identity (page id and historical ID)
in `archive/sessions/2026-09-04-m2-g1-pre-readiness-feature-rows-gaps.md`,
which their `evidence` field cites, satisfying G1's `closes_when` clause in
`docs/project/m2-closure-register.yaml`: "or an explicitly reviewed rule
classifies pre-readiness feature-scope rows as evidence-only."

**Exclusions, exact:**

- **Collision-kind rows** — any row whose page id or historical ID appears in
  `docs/decisions/id-collisions.yaml` is excluded; collisions are governed by
  the collision registry, not this rule, and are G2/G3's remit.
- **Git-native protocol labels** — any row whose id matches a heading of the
  form `<Name> Protocol (DEC-…)` in `CLAUDE.md`/`AGENTS.md`
  (`gitNativeClaims` in `scripts/m2-closure-register-lib.mjs`) is excluded;
  that id already carries live Git-native authority and is not this rule's to
  reclassify.
- **Existing formal record ids** — any row whose id already names a formal
  candidate record under `docs/decisions/records/` is excluded; that row is
  either cited by the record (`formally_migrated`) or otherwise collides with
  it and needs its own resolution, not this rule.
- **Non-feature scope** — global and temporary-scope rows are unaffected; 128
  global-scope and 1 temporary-scope `not_yet_reconciled` rows remain open
  after this rule and stay G1 batch work.
- **Post-readiness rows** — any row decided on or after 2026-08-12 (the
  `DEC-20260812-A` adoption date) is unaffected; it is not pre-readiness by
  definition and belongs to normal contradiction-checked batch work.
- **Non-`not_yet_reconciled` rows** — a row already `formally_migrated`,
  `unresolved_collision`, `resolved_collision`, `intentionally_historical`,
  `obsolete_or_superseded`, or `unclear` is untouched; this rule only ever
  moves a `not_yet_reconciled` row to `intentionally_historical`.

## Context

This record's `scope` is `operational`, not `global`. The rule is a
migration-scope technical classification applied to inactive M2 candidate
material (`authority_active: false`); it does not create, change, or reverse
any live product, pricing, or governance decision, and it carries no effect
outside the M2 closure register itself. It falls within the operating
charter (`DEC-20260815-A`): "architecture, implementation, what to measure,
what to build and in what order, testing, tooling, vendor-API choice are all
Claude's." The Workflow Invariant "Global decisions → ALWAYS get
confirmation" is therefore not triggered — this is not a global decision. If
a later batch needs to lift a row out of evidence-only into a formal record,
that batch decides on its own merits at that scope.

Feature-scoped decisions from Feb–Aug 2026 describe UI, website, and
capability-level choices that predate the readiness program. `DEC-20260812-A`
("Readiness program adopted") supersedes `DEC-20260502-A` (Counterparty
Assurance rename/ICP) and `DEC-20260503-A` (dual-domain architecture) and
retired the product framing those earlier feature-scoped rows served; the
website itself is being rebuilt inside this repository per `DEC-20260902-A`.
These 76 rows are therefore evidence of what was decided at the time, not
live authority a customer-facing surface should read from today. A formal
candidate record per row would be 76 records nobody would read, each needing
the same five-section fidelity bar as an active decision — disproportionate
to their evidentiary weight.

## Rationale

G1's `closes_when` clause in the M2 closure register explicitly admits this
path: "Every row reaches formally_migrated, intentionally_historical, or
obsolete_or_superseded through contradiction-checked batches, **or an
explicitly reviewed rule classifies pre-readiness feature-scope rows as
evidence-only.**" This record is that explicitly reviewed rule. The
population was measured mechanically by
`scripts/m2-closure-apply-g1-rule.mjs` against the private projection at the
pinned archive commit, dry-run by default, and the count (76) is reported
rather than assumed; the script's report was inspected before this record's
population figure was written, and the batch stopped rather than adjusted
the predicate if the number had not matched the 76 measured in the
orchestrator's brief.

The review route: a fresh, read-only Claude agent that did not author this
batch performs the independent review (per the founder's 2026-09-01
review-routing override and its 2026-09-03 amendment, `DEC-20260903-A`).
Because Codex quota remains a scarce resource this batch does not stop for,
this batch is recorded on `docs/programs/codex-review-backlog.yaml` by the
orchestrator (not by this batch, which does not edit that file) for the
Codex re-review that runs once quota returns.
