## Decision

Replace a planned three-sentence problem-statement Section 2 with an
animated visualization of an agent processing a batch of counterparty
verifications: deterministic preset data for 5 counterparties (3 proceed,
1 block, 1 review), an 8-second loop, an accessible fallback for
`prefers-reduced-motion`, `IntersectionObserver`-based start/pause, and a
mobile stacked variant. The row estimates "7-10 days of focused frontend
work (Framer Motion + React + TypeScript)."

## Context

The row's own reasoning: "all nine reference sites the user liked (Stripe,
Mercury, StackAI, Hyperagent, Mintlify, Gumloop, Arva) use product-in-use
motion as primary visual content; showing the product solve the problem is
stronger than describing the problem." It states the preset response data
"must stay in sync with sandbox presets and production API response
shape," creating what it calls "a three-surface schema contract (landing
animation, sandbox, production)." The row names no other Decision ID, and
its sibling row under this collision (the Phase 4 split) does not name this
row either; no relation edge is recorded between the two.

## Rationale

The rationale, as the row states it: peer sites in the same product
category use product-in-use motion, not descriptive prose, as their primary
hero-adjacent content, and demonstrating the product is a stronger
persuasion mechanism than describing the problem it solves.
