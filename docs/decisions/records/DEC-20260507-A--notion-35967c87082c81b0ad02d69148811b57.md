## Decision

Move the drift-check substrate to `platform-facts.ts`. Static maps inside CI
scripts that mirror canonical vendor content are deprecated as a class.

## Context

The row's Rationale states: "Drift-check scripts derive their reference lists from platform-facts.ts via getActiveVendorNames() and getStaleVendorNames() helpers. Static maps inside CI scripts that mirror canonical content are deprecated as a class — they are themselves drift-prone surfaces and have caused two course-correction incidents in two months (OpenSanctions self-host claim 2026-05-01; OpenOwnership BODS aspirational claim 2026-05-07)."

## Rationale

Per the row: "New invariant in platform-facts.test.ts: every name in getActiveVendorNames() corresponds to a shipped capability slug under apps/api/src/capabilities/."

## Consequences

Status on 2026-09-05, verified in files: `apps/api/src/lib/platform-facts.ts`
exports `getActiveVendorNames()` (line 164) and `getStaleVendorNames()` (line
171). `apps/api/scripts/check-platform-facts-drift.ts` imports
`getStaleVendorNames` (lines 41 to 43; `getActiveVendorNames` appears only
in its header comment and is imported by `platform-facts.test.ts` instead) and its own header comment states: " Reference lists derive from `apps/api/src/lib/platform-facts.ts` via `getActiveVendorNames()` and `getStaleVendorNames()`. The unit test in `platform-facts.test.ts` asserts every name in `getActiveVendorNames()`". CLAUDE.md's drift-prevention section names the same
canonical-source pattern for other cross-surface facts ("update **only** the canonical source and let consumers read from it"), consistent with this
row's mechanism. This decision's specific substrate holds as described.

## Reversal conditions

Supersede this decision if the drift-check mechanism moves off
`platform-facts.ts` to a different canonical source, or if static
per-script vendor maps are reintroduced deliberately for a documented reason.
