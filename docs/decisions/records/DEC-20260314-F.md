## Decision

Adopt AX (Agent Experience) as a first-class quality dimension, applied
through three concrete items: a zero-auth MCP path, actionable errors, and
an autonomous completion rate metric.

## Context

The row's stated basis, from its own Rationale: "2027.dev Agent Arena
research (60+ devtool AX evaluations) found: auth caused 40% of agent
interruptions, docs problems caused 68% of failures, top tools averaged
0.2 human interruptions vs 4.7 for bottom tools. Strale's primary
consumers are AI agents, AX is not a nice-to-have, it's the core product
experience." The row states the decision was applied to Sprint 9F
(elevated to five free capabilities via MCP without auth), Sprint 11E (a
new AX audit item), and Sprint 11D (tool description optimization), and
that autonomous completion rate was adopted as a key metric.

The historical Notion scope field on this row was `global`. It is
recorded here as `scope: product`: it sets a product quality dimension
and roadmap emphasis, not a company-wide strategic or positioning
decision on its own.

## Rationale

The rationale, as the row states it: agents are the platform's primary
consumer, and the cited external research ties auth walls and poor
documentation directly to agent task failure and interruption rates. If
AX is not tracked and improved deliberately, the platform optimizes for
a human evaluator that is not the one actually calling it.

## Consequences

Status verified on 2026-09-05, against `main`.

**The zero-auth MCP path exists, but only partially.**
`packages/mcp-server/README.md` states: "`strale_ping`, `strale_search`,
`strale_methodology`, and `strale_trust_profile` work without an API
key. `strale_execute` and `strale_balance` require authentication," and
separately: "*Free-tier capabilities work without an API key." CLAUDE.md's
free-tier paragraph independently confirms 11 capabilities require no
auth or signup, surfaced via `GET /v1/platform/facts`
(`free_tier_slugs`). So the zero-auth path is real for a defined slice
of the catalog and four read-only MCP tools, not for the catalog as a
whole, matching the row's own framing of "five free capabilities via
MCP without auth" rather than a fully open platform.

**Actionable errors exist as a platform-wide contract, not something
built specifically for this row.** CLAUDE.md's Active Decisions list
records DEC-19 ("Structured error responses with stable error_code
enum") as already active at the time this row was written, and that
contract remains the platform's error shape today. This record does not
attempt to verify whether DEC-19 was extended in response to this row
or was already in place; either way, structured, actionable errors are
the current behavior.

**No autonomous completion rate metric exists in code today.** A
targeted search (`grep -rn "completion_rate\|autonomous"
apps/api/src/lib/metrics*`, and a repo-wide
`grep -rln "completion_rate\|autonomous_completion\|autonomousCompletion"
apps/api/src`) returns zero matches anywhere under `apps/api/src`. Of the
three concrete items the row names, this is the one with no evidence of
having shipped, in the metrics layer or anywhere else in the API source.

**Sprint 9F, 9E/9F/11D/11E numbering is not tracked in the repository.**
No file under `docs/strategy/` mentions "Sprint" (`grep -rln "Sprint"
docs/strategy/*.md` returns nothing). The sprint framework the row
describes has no surviving trace in the current documentation set; this
record cannot confirm whether Sprint 9F, 11D, or 11E shipped as
described.

## Reversal conditions

None recorded on the row (`Superseded By` and `Outcome` are both null).
A metrics-layer change adding an autonomous completion rate signal, or a
widening of the zero-auth MCP path beyond the current free-tier slice,
would be the natural successor; until then, two of the three named items
(zero-auth path for a defined subset, actionable structured errors) hold
and the third (the completion-rate metric) does not appear to have been
built.
