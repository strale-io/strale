## Decision

Positioning: global platform, EU/Nordic capability wedge. Brand, API,
SDK, and docs are global from day one. The first five capabilities lean
EU/Nordic as a defensible edge. Geographic expansion proceeds through
monthly capability additions and, eventually, through external providers
from other regions. Reject both "EU-only niche" and "pretend global
coverage."

## Context

The row's stated basis, from the row's own Rationale: Gemini and ChatGPT
both initially recommended a deep EU focus, then both pivoted when the
founder said "global"; Gemini's pivot (API arbitrage/reselling) was judged
to create thin margins and dangerous dependencies; ChatGPT's pivot
(global deterministic data) was judged the right framing but proposing
capabilities that require multi-country data infrastructure a solo
founder cannot build. Resolution, per the row: global brand plus
EU/Nordic starting capabilities plus deliberate geographic expansion,
described as "honest about coverage, ambitious about trajectory."

The historical Notion scope field on this row was `global` in the
workspace's old vocabulary. It is recorded here as `scope: product`: this
is a market-positioning choice, not a single technical integration.

## Rationale

The rationale, as the row states it: two independent LLM reviewers both
initially proposed EU-only framings and both pivoted toward "global" once
directed, but neither pivot alone was judged buildable or economically
sound by a solo founder (thin-margin API reselling on one side,
multi-country infrastructure the founder cannot build alone on the
other); the row resolves this by keeping the brand and product surface
global while being honest that early capability coverage is EU/Nordic.

## Consequences

Status verified on 2026-09-04, against `main`.

**No explicit "global platform" or "EU/Nordic" positioning claim was
found registered in the platform's current public-claims machinery.** A
grep of `docs/company/VOICE.md` and `docs/company/claims.yaml` for
"global," "EU/Nordic," and "nordic" (case-insensitive) found no match in
`VOICE.md` and only an unrelated mention in `claims.yaml` (a comment about
"the static global price range"); this suggests the specific positioning
language this row sets is not currently tracked as a public claim subject
to `npm run claims:check`, one way or the other.

**CLAUDE.md's current capability description is consistent with the
row's "wedge, not niche" framing, in substance.** CLAUDE.md's project
memory describes the platform as vertical-agnostic with a KYB/compliance
wedge (not geography-scoped), and its capability paragraph lists "7
verticals (company-data, compliance, developer-tools, finance,
data-processing, web-scraping, monitoring)" without restricting the
platform's brand or API surface to the EU/Nordic region, consistent with
this row's "brand, API, SDK, docs are global from day one" clause; the
present-day wedge, however, is framed by vertical (KYB/compliance) rather
than by this row's geography (EU/Nordic capability count), so the two
"wedge" concepts are not the same wedge.

**The row's "eventually through external providers from other regions"
clause has not materialized**, per the verification recorded on
`DEC-20260225-P-g9h0`'s Consequences: no third-party provider of any
region has been onboarded to date.
