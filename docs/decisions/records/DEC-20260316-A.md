## Decision

Eliminate the Combined Trust Grade (a worst-of A/B/C/D letter combining SQS
score, freshness, and latency) from all surfaces.

## Context

The Combined Trust Grade was a worst-of roll-up of the SQS score
(the dual-profile matrix output, itself the "issuer rating" headline
signal), a freshness grade, and a latency grade. The historical Notion
scope field on this row was `global`. It is recorded here as `scope:
product` under this repository's decision-record vocabulary: this decision
governs what quality signal customers and downstream AI agents see, a
trust-display concern.

## Rationale

The Combined Trust Grade created a competing letter that confused which
signal was "the" rating: SQS was already meant to be the single headline
signal, and a second, worst-of letter grade sitting alongside it
undermined that. The decision states it was validated by ChatGPT and Claude
evaluations: neither model referenced or used the Combined Trust Grade in
practice, and both relied on SQS as the primary quality signal. Freshness
and latency were kept as functional API filter parameters
(`require_fresh`, `max_latency_ms`) and as descriptive metadata on detail
pages, but not as letter grades competing with SQS.

## Consequences

Status verified on 2026-09-04, against `main`.

**No Combined Trust Grade is wired into any live API response, but the
function that computes one still exists as dead code.**
`apps/api/src/lib/trust-grade.ts` still defines `computeTrustGrade`
(`export type TrustGrade = "A" | "B" | "C" | "D"`, worst-of roll-up of an
SQS-derived grade, a freshness grade, and a latency grade — structurally
the same shape this row eliminates) under a section header literally
titled "Combined Trust Grade." A repository-wide grep for
`computeTrustGrade` across `apps/api/src` finds zero call sites outside
`trust-grade.ts` itself: nothing imports or invokes it. `apps/api/src/routes/do.ts`,
the file that does import from `trust-grade.ts`, imports only
`computeFreshnessGrade` — the freshness component this row explicitly
permits to survive as descriptive metadata — not `computeTrustGrade`. A
grep for `trust_grade` (the field-name form) and `combined` (case-
insensitive) across `apps/api/src` finds no field named `trust_grade` or
`combined_trust_grade` in any route response. Stated plainly: the letter
grade this row eliminates does not appear on any surface today, but the
function that would compute it was never deleted from the codebase, only
left unreferenced.

**`apps/api/src/routes/public-trust.ts` reaffirms the same rule under a
different rationale.** Its own header comment states: "The retired SQS
grades, guidance strategy, and raw sub-scores are deliberately NOT
projected: they were retired, and reviving them here would recreate a
scoring surface the platform decided to stop publishing" — this row's
"one headline signal" principle, restated after the SQS engine itself was
deleted (DEC-20260503-B, 2026-05-05).

**The SQS score this row's grade was built from no longer exists.** Per
DEC-20260503-B, the dual-profile matrix SQS score is gone; a grade
combining "worst of SQS, freshness, latency" has no live SQS input to
combine even if `computeTrustGrade` were called.

## Reversal conditions

Reconsider this decision if a future surface calls `computeTrustGrade` or
otherwise reintroduces a worst-of letter grade competing with a primary
quality signal; the dead-code function's continued presence in
`trust-grade.ts` should be treated as a latent risk to clean up (delete or
re-justify), not as evidence the rule is inactive. Represent a change of
this decision through a new decision rather than editing this protected
record in place.
