## Decision

A build sequence established: a 20-step dependency-ordered plan running
from distribution multipliers (an MCP server, A2A, framework plugins)
through a reputation registry to enterprise integrations. Distribution
comes before content, data collection before analysis, and compliance
before enterprise sales.

## Context

The row's stated basis, from the row's own Rationale: synthesized from
research on giant platforms' own initiatives, protocol ecosystems, and
the competitive landscape. The key insight the row states: steps 1
through 4 (an MCP server, registry listings, A2A Agent Cards, framework
plugins) are force multipliers, because every capability added after them
reaches exponentially more agents. The row states a 6-9 month window to
establish Strale as the de facto A2A Agent Card registry drives urgency on
steps 3, 10, 11, and 14; EU AI Act enforcement (dated 2026-08-02 in the
row) drives urgency on step 5.

The historical Notion scope field on this row was `global` in the
workspace's old vocabulary. It is recorded here as `scope: product`: this
is a roadmap-sequencing decision, not a single technical integration.

**Relation to `DEC-20260227-P-s9t0`.** This row's Decision text names "a
reputation registry" as a build-sequence destination, the same phrase
`s9t0` uses for its reframed Unit 2 ("the A2A reputation registry"); this
row is recorded as `related_to` `s9t0` on that shared term. This row does
not name `DEC-20260227-P-q7r8`'s specific unit names ("Capability
Marketplace," "Commerce Protocol") or the phrase "three units," so no
edge is recorded to `q7r8` under this batch's source-stated-only rule.

## Rationale

The rationale, as the row states it: distribution-multiplying steps (MCP
server, registry listings, Agent Cards, framework plugins) should come
first because each one compounds the reach of every capability added
after it; a narrow window exists to become the de facto A2A registry
before someone else does, and EU AI Act enforcement timing separately
forces the compliance-related step earlier in the sequence than it would
otherwise sit.

## Consequences

Status verified on 2026-09-05, against `main`.

**Several of the row's named "distribution multiplier" steps exist on
`main` today; the plan's 20-step sequence itself is not tracked anywhere
in the repository, so which of the 20 steps shipped in which order cannot
be verified against the plan's own numbering.** An MCP server exists

"Distribution packages & protocol endpoints" area (per its "Feedback"

found that reproduces or references this row's specific 20-step numbered
list; this verification cannot say, step-by-step, which of the 20 shipped
in which order, only that the category of work the row calls "force
multipliers" (MCP server, A2A, framework plugins) exists today.

**The "de facto A2A Agent Card registry" ambition this row's urgency
argument rests on was not found built.** As `DEC-20260227-P-s9t0`'s
Consequences establish, no ecosystem-wide indexing or scoring of other
agents' A2A Agent Cards was found on `main`; Strale's A2A route serves its
own capability surface, not a registry of third parties.
