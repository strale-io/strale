## Decision

Solution discovery UX uses a smart input that looks like a search bar
but returns a single AI recommendation card with actions, not a chat
interface, not traditional search.

## Context

The row's stated basis, from its own Rationale: three options were
evaluated, (A) a traditional search bar, familiar but with no wow
factor; (B) a full chat interface, high friction and page-dominating;
(C) a smart input that looks like a search bar but returns a single AI
recommendation card with actions. Option C was chosen for five stated
reasons: (1) it maps directly to `POST /v1/suggest`, the same endpoint
agents use via MCP, so the website itself is a live product demo; (2) it
gives progressive disclosure, one answer first, conversational
follow-up only if needed; (3) it has the highest wow-to-friction ratio;
(4) it scales as the catalog grows, since intent matching improves with
more capabilities; (5) the row states the Discovery & Navigation spec
already described this pattern. Named UX details: rotating placeholder
examples in the input, a single recommendation card with Try/Details/Copy
actions, and a "Not what you need? Tell me more" expansion into a
follow-up input.

This historical ID is reused by a second, unrelated Notion row (the
Problem→Solution SVG-diagram decision made the same day) and was an
unresolved registry collision until this batch; the two rows are
resolved together in
`archive/sessions/2026-09-05-decision-collision-resolution-DEC-20260303-A.md`
with distinct source-qualified record keys. This record covers only the
smart-input discovery UX row.

## Rationale

The rationale, as the row states it: a chat interface asks too much of
the visitor and a plain search bar demonstrates nothing about the
product; a smart input that resolves to one AI-picked recommendation
turns the homepage into a working demo of the same matching mechanism
agents use, while staying low-friction and progressively disclosing more
detail only on request.

## Consequences

Status verified on 2026-09-05, against `main` and the sibling
`strale-frontend` checkout, read-only.

**The endpoint the row names is live.** `apps/api/src/routes/suggest.ts`
defines both `GET /v1/suggest/typeahead` (public, no auth, in-memory
matching) and `POST /v1/suggest` (public, no auth required, the
AI-recommendation endpoint), matching the row's "maps directly to
`POST /v1/suggest`" claim.

**Rotating placeholder examples exist.**
`strale-io/strale-frontend@04c9fca9:src/components/solutions/SearchHero.tsx`
defines a `placeholderIdx` state rotating through `PLACEHOLDER_QUERIES`
in the search input, matching the row's "rotating placeholder examples"
detail. A code comment in the same file notes "`GET /v1/suggest/typeahead`
and the SQS engine itself is gone," reflecting the later SQS-engine
deletion (DEC-20260503-B) as an implementation change layered on top of
this row, not a reversal of the smart-input pattern itself.

**The follow-up prompt matches byte-for-byte.**
`strale-io/strale-frontend@04c9fca9:src/components/solutions/RecommendationCard.tsx`
renders the text "Not what you need? Tell me more →", matching the row's
named UX detail exactly, arrow included.

**A single recommendation card with actions is still the pattern**, not
a chat interface or a bare results list: `RecommendationCard.tsx`
renders a "Copy code" action (with a `Copy` icon) among its interactive
elements, consistent with the row's "Try/Details/Copy actions"
description; this record did not independently re-verify every one of
the three named actions (Try, Details, Copy) individually.

## Reversal conditions

None recorded on the row (`Superseded By` and `Outcome` are both null in
the source). A future redesign replacing the single-recommendation
smart input with a chat interface or a traditional multi-result search
would supersede this row.
