## Decision

Restructure the capability and solution detail page section order to:
Header (price + inline SQS) then How it works / Parameters then Try it
(code + CTAs) then Quality (SQS hero + breakdown) then Test results then
Limitations then Extend/Used in then Accountability then Related. The
quality dot merges into the price line to eliminate duplication with the
SQS hero section below. The same order applies to both solutions and
capabilities.

## Context

The row's stated basis, from its own Rationale: the previous order put
the SQS trust card and score breakdown above "How it works" and "Try it,"
so developers scrolled through quality proof before seeing the value
proposition or code examples. The new order moves the value proposition
(how it works, try it) earlier and the trust/quality proof later, framed
in the row's title as "understand, try, trust, explore."

The historical Notion scope field on this row was `global`. It is
recorded here as `scope: product`: it specifies page-section ordering,
a UI composition decision, not a company-wide strategic or purely
technical one.

## Rationale

The rationale, as the row states it: leading with quality proof (SQS
score, breakdown) before the value proposition (how it works, try it)
put proof of quality ahead of the reason to care about the capability at
all; reordering to understand-then-try-then-trust-then-explore fixes
that sequencing.

## Consequences

Status verified on 2026-09-05, against the sibling `strale-frontend`
checkout, read-only, on 2026-09-05.

**The understand-then-try ordering survives; the "trust" section as this
row specified it (an SQS hero plus score breakdown) does not, because the
SQS engine it depended on was deleted.**
`strale-io/strale-frontend@04c9fca9:src/pages/CapabilityDetail.tsx` renders, after the
header/price block: "Parameters" (line 271), "One API call. Structured
data." (the try-it code block, line 304), "Part of these solutions"
(line 319), then a section explicitly commented "HOW THIS IS VERIFIED —
Replaces the former 'Quality & Transparency' SQS tabs (ZoneBReliability /
ZoneCCompliance), which depended entirely on
GET /v1/public/ops/trust/capabilities/:slug and .../compliance-profile —
both deleted from the backend along with the SQS scoring engine
(DEC-20260503-B, 2026-05-05)," then "Related guides" (line 432); the
file has no limitations section (a grep for "limitation" finds nothing). A separate comment near the header block
states: "SQS/quality-profile display removed: the scoring engine backing
it (Strale Quality Score, GET /v1/public/ops/trust/capabilities/:slug)
was deleted from the backend 2026-05 (DEC-20260503-B)."

This confirms the understand (parameters) then try (code example) then
explore (related solutions, related guides) shape of the row's ordering
survives, but the distinct "trust" section (an SQS hero plus score
breakdown, positioned between try-it and test results) does not exist as
specified: it was replaced by a "how this is verified" section built from
fields the live `/v1/capabilities/:slug` response and example-output
fixtures actually return, not from a score. The "quality dot merged into
price line" instruction this row also specified cannot be verified as a
literal price-line quality dot, because the SQS-derived score it would
have displayed no longer exists; a latency annotation (p95, derived from
`avg_latency_ms`) appears near the price block instead, per the same
file's header-region comments.

## Reversal conditions

None recorded on the row (`Superseded By` and `Outcome` are both null in
the source). `DEC-20260503-B` is the decision that removed the scoring
engine this row's "trust" section depended on, though it does not name
this historical ID directly; a future decision formally recording the
post-SQS detail-page section order (as the "HOW THIS IS VERIFIED" section
now implements it) would supersede this row's specific trust-section
design while likely keeping its broader understand/try/explore sequence.
