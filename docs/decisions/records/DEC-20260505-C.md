## Decision

Replace the SQS-based matching tiebreaker (`matrixSqs DESC`) with `priceCents
ASC, slug ASC`. Replace the solutions auto-gate (previously requiring
`matrixSqs > 0` across all step capabilities) with: every step capability
must have at least one passing `test_result` in the last 30 days.

## Context

The row's own Rationale states the trigger and the reasoning: "PR1 (commits
6e71d7d -> ae338fb, pushed 2026-05-05) deleted the SQS scoring engine.
matrixSqs was previously the primary tiebreaker for capability matching when
multiple capabilities serve the same (evidence type x country) routing.
Replaced matrixSqs DESC with priceCents ASC, slug ASC. Rationale: cheapest
provider wins (aligns with bundle pricing economics and Counterparty
Assurance margin); alphabetical slug ensures determinism when prices match."
The row states "Implements DEC-20260503-B (SQS public-score retirement)," so
`affirms DEC-20260503-B` is recorded (that record exists on the PR head).

## Rationale

As the row states it, on the solutions gate replacement: "previously a
solution required matrixSqs > 0 across all step capabilities. Replaced
with: every step capability must have at least one passing test_result in
the last 30 days. Mirrored in seed-solutions.ts." The row records a measured
side effect: "Prepush diagnostics confirmed 2.7% (3 of 113) solutions
cascade-deactivate on first scheduler tick post-deploy — all 3 are SG
solutions blocked on singapore-company-data, flagged for separate
investigation."

## Consequences

Status verified on 2026-09-05, against `main`.

**The price/slug tiebreaker is live exactly as this row describes, with a
code comment explicitly citing this decision by ID.** `apps/api/src/lib/matching.ts`'s
`betterRate` function reads:

```
  // Tiebreaker: cheaper price wins; equal price → alphabetical slug.
  // Replaces the SQS-DESC tiebreaker retired with the SQS engine
  // (DEC-20260503-B). Deterministic and price-aware so a low-cost
  // capability is preferred when match quality is identical.
  if (a.priceCents !== b.priceCents) return a.priceCents < b.priceCents;
  return a.slug < b.slug;
```

This matches the row's stated order (`priceCents ASC`, then `slug ASC`)
exactly. The comment cites `DEC-20260503-B` (the SQS deletion) rather than
this row's own ID, consistent with this row's own framing of the change as
an implementation of that decision.

**This record did not independently verify the current state of the 3
flagged Singapore solutions** (`singapore-company-data`-blocked
cascade-deactivations); the row itself flags them "for separate
investigation" rather than as resolved, and no evidence file in this
repository was found tracking that specific investigation's outcome.
