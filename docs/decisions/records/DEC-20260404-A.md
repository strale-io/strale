## Decision

Adopt Glama's Tool Definition Quality Score (TDQS) as a quality signal;
rewrite `strale-mcp` tool descriptions to pass all six criteria.

## Context

The historical Notion scope field on this row was `global`. It is recorded
here as `scope: technical` under this repository's decision-record
vocabulary: this decision is a publication and rail mechanic (bringing the
`strale-mcp` package's own listing metadata up to a third-party quality
bar), not a positioning choice.

## Rationale

Glama (Frank Fiegel / punkpeye) launched the Tool Definition Quality Score
on 2026-04-03. Glama is one of the largest MCP server directories and a
material distribution surface for Strale. TDQS grades tool definitions on
six criteria: clear purpose, usage guidelines, behavior explanation,
semantic parameters, conciseness, and contextual completeness. Pre-work,
Strale's Glama listing showed License F (no LICENSE file picked up),
Quality not tested, and 8 exposed meta-tools pending TDQS scoring. Two of
the three overview scores (security, license) self-corrected to A once
Glama re-scanned, leaving only quality untested. Running the rewrite served
three goals: (1) flip quality from pending to A on Glama; (2) create
natural standing to engage with punkpeye's framework from a position of
having participated; (3) set a cleaner public bar for tool description
quality that the ecosystem can compare against. The rewrite architecturally
validated that `strale-mcp` correctly exposes 8 meta-tools
(`strale_balance`, `strale_execute`, `strale_getting_started`,
`strale_methodology`, `strale_ping`, `strale_search`, `strale_transaction`,
`strale_trust_profile`) rather than 271 individual capabilities — exposing
all capabilities would blow agent context windows. The rewrite targeted
only these 8 meta-tools, not the underlying capability registry. Parameter
names were verified semantic (`slug`, `inputs`, `max_price_cents`, `query`,
`category`, `offset`, `transaction_id`, `type`) and preserved unchanged to
avoid breaking the public API contract. Shipped as `strale-mcp@0.2.4` on
npm. Expected outcome: all 8 tools score 6/6 on TDQS at the next Glama
re-scan within 24-48 hours.

## Consequences

Status verified on 2026-09-04, against `main`.

**The Outcome this row recorded was "Pending Glama re-scan"; no repository
document records Glama's own re-scan result.** A repository-wide search for
`TDQS` finds only `archive/sessions/audit/2026-04-04-strale-mcp-tdqs-rewrite.md`,
which is the platform's own before/after self-scoring for the rewrite
described above — it records all 8 tools moving from an average of 4.0/6
before the rewrite to 6.0/6 after (`strale_ping` 4→6, `strale_getting_started`
4→6, `strale_execute` 4→6, `strale_search` 3→6, `strale_balance` 3→6, and
so on), and confirms no parameter renames occurred. This is the platform's
self-scoring against Glama's published rubric, not Glama's own re-scan
verdict; whether Glama's independent re-scan confirmed 6/6 for all 8 tools
remains unrecorded in this repository.

**All 8 meta-tools this row names still exist in the current codebase.**
`packages/mcp-server/src/tools.ts` still defines `strale_ping`,
`strale_getting_started`, `strale_execute`, `strale_search`,
`strale_balance`, `strale_methodology`, `strale_trust_profile`, and
`strale_transaction`.

**The tool descriptions have since been rewritten again, for a different
reason: to remove references to the SQS engine this row's rewrite (and
Glama's re-scan) would have described.** `packages/mcp-server/src/tools.ts`
carries a comment stating the descriptions must describe "what the API
actually returns — no retired concepts (the SQS scoring engine was
[deleted])", and further states lifecycle now exposes `lifecycle_state` and
`last_tested_at` but "do NOT expose a numeric quality score. The dual-profile
SQS engine retired 2026-05-05," citing "DEC-20260503-B (SQS deletion)."
This is a later, unrelated rewrite (driven by the SQS engine's 2026-05-05
deletion, not by TDQS) that happens to touch the same file this row's
rewrite touched; it does not reverse this row's adoption of TDQS as a
signal, but it means the exact tool-description text this row's rewrite
produced no longer exists verbatim in the codebase.

**`glama.json` at the repository root carries no TDQS-specific content
today** — only a `maintainers` list (`petterlindstrom79`,
`petterlindstrom`) — so the file itself is not where a TDQS result would be
recorded even if Glama's re-scan verdict were available.

## Reversal conditions

Reconsider this decision if Glama's TDQS framework is retired or replaced
by a different quality signal, or if `strale-mcp`'s tool descriptions drift
below the six-criteria bar again without a corrective rewrite. Represent a
change of this decision through a new decision rather than editing this
protected record in place.
