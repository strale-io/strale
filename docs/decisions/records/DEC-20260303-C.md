## Decision

Publish the ranking algorithm explanation; transparent ranking is a core
trust signal and differentiator, unlike most marketplaces that hide
their ranking logic. Three surfaces: (1) a "Why this recommendation?"
expandable on every recommendation card showing the specific factors for
that result, (2) a dedicated `/how-ranking-works` page explaining every
ranking factor, weight, and explicitly stating "Strale does not accept
payment for ranking position," (3) future provider docs telling providers
how to rank higher (answer: ship better quality, not pay more). Ranking
factors, in priority order: semantic match quality, trust score (test
pass rate + transaction volume + badge level), provider reputation
(future), price efficiency (quality-adjusted, not cheapest-wins),
geography proximity, and popularity as a tiebreaker. Sort controls on the
card grid (Recommended / Price / Quality / Newest) reinforce transparency
by letting developers choose their own ranking criteria.

## Context

The row's stated basis, from its own Rationale: Strale positions itself
as the trust layer, and ranking transparency is a core differentiator
from marketplaces that hide their ranking logic.

The historical Notion scope field on this row was `global`. It is
recorded here as `scope: product`: it specifies UI surfaces (a card
control, a dedicated page) and a public-facing content commitment, not a
company-wide strategic or purely technical decision.

## Rationale

The rationale, as the row states it: publishing ranking logic openly,
rather than hiding it as most marketplaces do, is itself the trust
signal. Naming "Strale does not accept payment for ranking position"
explicitly forecloses a common marketplace trust problem before it can
be asked about.

## Consequences

Status verified on 2026-09-05, against `main` and the sibling
`strale-frontend` checkout, read-only.

**No dedicated `/how-ranking-works` page or "Why this recommendation?"
card control was found.** `strale-io/strale-frontend@04c9fca9:src/App.tsx` routes `/trust`
and `/trust/methodology` to the same `Methodology` component (no
`/how-ranking-works` route exists). `strale-io/strale-frontend@04c9fca9:src/pages/Methodology.tsx`
carries a header comment (added post-SQS-deletion) stating it "previously
documented the 'Strale Quality Score' (SQS)... That entire scoring
engine... was deleted from the backend 2026-05-05 (DEC-20260503-B)" and
is "rewritten to describe only what the live platform actually does" , 
its content today is the five test types (known answer, schema check,
negative, edge case, dependency health), not a ranking-factor
explanation or a no-pay-for-position statement. A search of the page for
"ranking" or "Why this recommendation" found neither term.

**A "Trust" nav link exists** (see `DEC-20260313-E`'s Consequences for
the direct evidence: `Header.tsx` line 10) and routes to this same
Methodology page, so the row's dedicated-page intent survives in form
(a published methodology page reachable from top-level nav) but not in
the specific ranking content this row specified.

**A ranking mechanism exists today, but it is not the one this row
described.** `apps/api/src/lib/seller-rank.ts` orders discovery surfaces
(the agent card, the x402 discovery catalog) by external revenue over a
rolling window, explicitly filtering out the internal test harness
(documented in the module's own header comment, citing the ~98%-internal-
traffic problem from `docs/company/MEASUREMENT.md`). This is a different
mechanism from the semantic-match/trust-score/price-efficiency/geography
factor list this row specifies. Separately, `apps/api/src/lib/suggest.ts`
implements the `POST /v1/suggest` endpoint's own ranking: Voyage AI
embeddings plus a Claude Haiku re-ranking pass (DEC-20260303-E, a
different, already-formal decision), which is closer in spirit to
"semantic match quality" but is not published to users as an explained
ranking-factor list, and carries no public no-pay-for-position statement.

**No evidence found of a "Strale does not accept payment for ranking
position" public statement** anywhere in the frontend pages checked
(`Methodology.tsx`, `Header.tsx`, `App.tsx` routes).
