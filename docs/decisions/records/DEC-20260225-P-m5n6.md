## Decision

Fuzzy input resolution on the Swedish company lookup: accept natural
language (the row's own example: "that shoe company in Stockholm founded
by Bjorn") and use a cheap LLM call to resolve it to an org number before
hitting the registry. Implement from day one on the `swedish-company-data`
capability.

## Context

The row's stated basis, from the row's own Rationale: ChatGPT suggested a
"fuzzy input advantage" as the difference between a plain API wrapper and
an intelligent capability. The idea is that a developer passes a vague
description, and Strale resolves it to the exact identifier, for the cost
of one cheap LLM call and a high perceived value gain, making
`strale.do()` feel like magic rather than a traditional API call. The row
targets implementation on `swedish-company-data` "in week 1-2."

The historical Notion scope field on this row was `global` in the
workspace's old vocabulary. It is recorded here as `scope: technical`:
this is an implementation approach for a single capability's input
handling, not a company-wide strategic or positioning decision.

## Rationale

The rationale, as the row states it: a fuzzy-input capability is
low-marginal-cost (one cheap LLM call) and high-perceived-value, turning
an API wrapper into something that reads as intelligent; it is worth
building into `swedish-company-data` immediately rather than deferring.

## Consequences

Status verified on 2026-09-05, against `main`.

**No LLM call and no fuzzy natural-language resolution exist in
`swedish-company-data` today; the capability's input contract requires an
exact org number.** `manifests/swedish-company-data.yaml`'s
`input_schema` lists `org_number` as the sole required field, described as
"Swedish organisationsnummer (10 digits, e.g. 556703-7485)." A search of
`apps/api/src/capabilities/swedish-company-data.ts` for any model,
Anthropic, or LLM reference, or the word "fuzzy," found none. No import
from `apps/api/src/lib/models.ts` (the sole permitted source of a
Claude/Voyage/GPT model id, per CLAUDE.md's "Model registry" section)
appears in the executor. This capability takes a precise identifier and
returns registry data; it does not resolve a vague description to one.

**CLAUDE.md still lists this row as an active decision, unqualified.**
CLAUDE.md's "MVP Decisions (Feb 2026)" section carries the line
"`DEC-20260225-P-m5n6`: swedish-company-data accepts fuzzy natural-language
input; cheap LLM call resolves to org number before registry lookup" with
no caveat that the feature is unbuilt. This verification found the
opposite of what that line asserts is running in production: a comment in
prose is not evidence the capability behaves as described (the same
lesson `DEC-20260904-C` records for a different filter). This record does
not attempt to resolve whether CLAUDE.md's line was ever true and later
regressed, or was aspirational from the start; it was not found in the
executor at either point checked (this verification and
`DEC-20260225-P-w9x0`'s, which found `swedish-company-data`'s price and
data source both changed since, without touching this input-handling
question).
