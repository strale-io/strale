## Decision

Enable branch protection on `main`: required pull request, required status
checks, strict base branch, and enforcement on admins (no bypass).

## Context

The row's Rationale states: "Closes the 2026-05-06 incident root cause (no branch protection on main; direct pushes allowed; F-0-014 lint guard fired correctly but was informational only). Verbatim read-back captured from direct-push attempt: GH006 'Protected branch update failed' with both 'Changes must be made through a pull request' and 'Required status check check is expected' firing."

## Rationale

The row's own verbatim capture of the GH006 rejection is offered as direct
evidence that the protection this row describes was, at the time of
recording, actually enforced by GitHub against a real push attempt, not
merely configured and untested.

## Consequences

This repository has no file that can independently confirm current GitHub
branch-protection settings (they are a GitHub repository setting, not a
tracked file); this record cannot verify the rule is still enforced today
from the checkout alone. `CLAUDE.md`'s session contract states "`main` changes only through reviewed PRs merged on GitHub; pushing the working branch is routine backup and needs no approval" and its Git hooks section
states "pre-push refuses a direct push to `main`," both consistent with a
protected `main` remaining the operating assumption on 2026-09-05, but
neither is the GitHub setting itself.

## Reversal conditions

Supersede this decision if branch protection is deliberately relaxed (for
example, to allow a specific automation to push directly) and that change
is recorded here rather than left as silent drift.
