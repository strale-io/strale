## Decision

Weight a third-party provider's self-reported test evidence at 0.5x
against Strale's own independent tests, which count at 1.0x.

## Context

The row's stated basis, from its own Rationale: "Trust but verify.
Provider results are one evidence source, not the score. Creates right
incentive: providers who want high SQS ensure capabilities pass Strale's
independent tests. Per ATI spec Section 12."

The historical Notion scope field on this row was `global`. It is
recorded here as `scope: technical`: it specifies a scoring-input
weighting rule inside a quality-evaluation mechanism, not a company-wide
strategic decision. The row's Decision and Rationale text refer to
"Strale independent tests" and "provider results" in general terms; they
do not name DEC-20260317-G or any other Decision ID directly (both rows
share the same Notion `Source` link, a parent specification page, but
that is a shared-document reference, not a row citing another row), so
no relation edge is recorded here.

## Rationale

The rationale, as the row states it: a provider's own claims about a
capability's quality are one input, not the score itself, and weighting
them below Strale's own independent verification creates an incentive
for providers to make their capability actually pass Strale's tests
rather than only report favorably about it.

## Consequences

Status verified on 2026-09-05, against `main`.

**No third-party provider exists to weight evidence from.** As with
DEC-20260317-G, CLAUDE.md's DEC-4 ("Founder is the only provider for
first 3 months") has never been superseded; T10 batch 13's
DEC-20260224-P-a1b2 record and batch 14's DEC-20260227-P-a1b2 record
both find, with their own evidence, that no third-party provider was
ever onboarded. The scoring problem this row solves (weighting one
party's self-reported evidence against another's independent tests) has
never had a second party to apply to.

**The scoring mechanism this weighting was meant to feed, the SQS
engine, no longer exists, and no 0.5x/1.0x weighting of any kind was
found anywhere in the code that replaced it.** CLAUDE.md: "SQS scoring
engine deleted per DEC-20260503-B." A targeted search for a
self-reported-versus-independent weighting factor
(`grep -rn "0\.5" apps/api/src/lib --include=*.ts`, reviewed by hand)
finds no match anywhere referencing provider evidence, self-reporting, or
an independent-test weighting; every `0.5` hit in that search is an
unrelated CSS letter-spacing value in email templates. Both halves of
what this row describes (a provider to weight, and a weighting mechanism
to apply it in) are absent from the current system.

**What the onboarding pipeline verifies today is Strale's own execution
against its own fixture, not a provider's self-report at any weight.**
`apps/api/scripts/onboard.ts` executes the capability directly against
its `known_answer` fixture and verifies the result itself (CLAUDE.md:
"Verifies the known_answer test passes against live output"); there is
no separate provider-submitted evidence being discounted against it,
because there is no separate provider.

## Reversal conditions

None recorded on the row (`Superseded By` and `Outcome` are both null).
DEC-20260503-B deleted the scoring engine this weighting fed into; DEC-4
(never superseded) is why no provider evidence has ever needed weighting
in the first place.
