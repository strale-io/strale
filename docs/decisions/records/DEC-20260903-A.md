## Decision

Waiting for Codex costs more than proceeding. Work does not stop for the
Codex quota, and no track may be blocked on the Codex review path alone.
The fresh, read-only Claude agent that does not author a batch remains the
independent review. Every batch that would otherwise have gone to Codex is
recorded in `docs/programs/codex-review-backlog.yaml`. A row closes only by
a Codex verdict archived under `archive/` and cited by path, or by a
founder waiver naming its decision.

`npm run codex:check` enforces this against git, not prose: compared with
the merge-base on `main`, a row may not be deleted, move backward, reopen
once closed, change its commit or its recorded verdict, or have
`policy.review_by` pushed later without a founder decision; on the file
itself it refuses a commit the repository lacks, a reviewed row whose
evidence file is not a verdict for it, a waiver by anyone but Petter, a
decision id the repository does not record, and a row still pending past
`review_by`.

## Context

CLAUDE.md's Review routing section records the sequence this amends: a
2026-09-01 founder override moved independent review off Claude entirely
onto a fresh Codex task; a 2026-09-02 amendment substituted a fresh,
read-only Claude agent once Codex quota was exhausted, with a re-review
obligation once Codex returned. By 2026-09-03 that re-review obligation had
no tracking mechanism: nothing recorded which batches still owed Codex a
look once it came back. This decision adds that mechanism.

## Rationale

CLAUDE.md's own text states the rationale directly: "waiting for Codex costs
more than proceeding," so work should not stall on a quota outage, but the
review gap that creates should not simply be forgotten. A checked register,
enforced against git history rather than against prose a session could
edit, makes the debt durable and auditable instead of a promise.

## Consequences

The register (`docs/programs/codex-review-backlog.yaml`) and its checker
(`npm run codex:check`) exist and are wired into the repository as
described. `DEC-20260910-A` later amends the review-routing policy this
register was tracking debt against (making cross-provider review optional)
without deleting the register: the 2026-09-07 founder review policy meant
the debt this register tracked was retroactively waived, and all 36 rows
were closed `waived` by `DEC-20260910-A`, citing that decision. This record
and its register stay in force as the enforcement mechanism, even though no
new batches are added to it under the current review policy.

## Reversal conditions

Supersede or amend this decision if a future founder decision reinstates a
review-path obligation this register should track, or if the register
mechanism itself (`codex:check`) is replaced by a different enforcement
approach. Waiving or closing the register's existing rows, as
`DEC-20260910-A` already did, amends this decision's operative effect
without retiring the mechanism itself.
