## Decision

OpenSanctions' standard Commercial API tier, at EUR 0.10 per call, is
confirmed as covering Strale's reseller use case. Startup pricing is only
available on a bulk data license at 40K-plus calls per month, which does
not apply at Strale's zero-user stage at the time of this decision.

## Context

Jack Popescu (Senior AE, OpenSanctions) confirmed the standard Commercial
API tier at EUR 0.10 per call, contact `jack@opensanctions.org`. The row
records this as affecting `pep-check` (EUR 0.15 at the time),
`adverse-media-check` (EUR 0.20 at the time), and `sanctions-check`
pricing margins. The recorded Outcome: pricing confirmed, no action needed
yet, capabilities in draft state pending `OPENSANCTIONS_API_KEY`
configuration on Railway, to be revisited approaching production volume.
Confidence recorded as high.

The historical Notion scope field on this row was `global` in the
workspace's old vocabulary. It is recorded here as `scope: technical`
under this repository's decision-record vocabulary: this is a vendor
integration and pricing-input choice, not a product-facing decision.

## Rationale

The rationale is the vendor quote itself: a named OpenSanctions sales
contact confirmed a per-call price for the tier Strale's usage pattern
requires, ruling out the higher-volume startup tier as inapplicable at the
time.

## Consequences

Status verified on 2026-09-04, against `main`.

**The vendor relationship this row is about no longer backs any live
capability.** OpenSanctions was dropped as Strale's sanctions/PEP vendor on
2026-04-27 (commit `16ca790`, resolves on `main` at
`16ca790ef8dc4dc94e2733b4c660786d9be61255`); Strale is single-vendor on
Dilisense per `DEC-20260429-A` (title: "Keep sanctions and PEP on a
Dilisense wrapper and defer self-hosting",
`docs/decisions/records/DEC-20260429-A.md`). This row's EUR 0.10 cost
figure is a historical input to a pricing decision (`DEC-20260320-F`,
already a formal record on `main`) whose own Consequences already flag
that the OpenSanctions cost basis changed; this record does not repeat
that arithmetic.

**The OpenSanctions key is still registered, on purpose.** `config/env-manifest.yaml`
carries an `OPENSANCTIONS_API_KEY` row: `holder: railway`, `cost_class:
free`, `required_in: []`, `retired: 2026-04-27`, with a `cost_note` stating
that no code reads it (OpenSanctions was dropped as a vendor on 2026-04-27,
commit 16ca790, DEC-20260429-A single-vendor on Dilisense), and that the
key and the account are kept on purpose, per DQ-30 and the founder's call
of 2026-09-03, because the vendor may be needed again and the free tier
costs nothing to hold. `docs/company/DECISION-QUEUE.md` DQ-30 (`answered` · owner Petter ·
raised 2026-09-02T22:15Z · answered 2026-09-03) records the same choice in
Petter's own words: "leave Cobalt, EINsearch and sec-api in place, he will
activate them later; and keep the OpenSanctions and USPTO accounts rather
than closing them, since we might need them." So the account is kept, the
key is unread by any code path, and this row's confirmed price is
historical evidence for a relationship that is dormant, not active.

## Reversal conditions

Reconsider this row if Strale re-adds OpenSanctions as a live vendor
(directly, or alongside Dilisense); at that point the EUR 0.10 Commercial
tier figure recorded here would need re-confirmation against then-current
OpenSanctions pricing, since this row's own Outcome only committed to
revisiting "when approaching production volume," which did not occur before
the vendor was dropped.
