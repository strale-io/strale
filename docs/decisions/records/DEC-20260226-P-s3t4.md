## Decision

Add EU AI Act compliance hooks to transactions: `audit_trail` (a JSONB
execution trace), `transparency_marker` (capability classification), and
`data_jurisdiction` (data source location). Also add date-based API
versioning (a `Strale-Version` header) to middleware. The row states both
are low-effort, high-defensibility features that must be built before
external users arrive.

## Context

The row's stated basis, from the row's own Rationale: drawn from a
"Competitive Defense Strategy" document. The EU AI Act was due to begin
enforcement on 2026-08-02, five months from this row's decision date.
Compliance-by-default is framed as a structural weapon against US
competitors who would have to retrofit it later. API versioning from day
one is framed as following the Stripe playbook: trivial to add now,
painful to add later, and the strongest long-term switching cost.

The historical Notion scope field on this row was `global` in the
workspace's old vocabulary. It is recorded here as `scope: technical`:
this is a specific schema and middleware implementation decision, not a
company-wide strategic or positioning decision.

## Rationale

The rationale, as the row states it: EU AI Act enforcement was five
months away, and building compliance in from day one is judged cheaper
and more defensible than retrofitting it later, especially against
competitors who would have to retrofit; the same "build it now, cheaply"
logic is applied to API versioning, following the Stripe precedent.

## Consequences

Status verified on 2026-09-05, against `main`.

**All three columns exist on `main` today and are actively written, not
merely schema placeholders.** `apps/api/src/db/schema.ts` declares
`auditTrail: jsonb("audit_trail")`, `transparencyMarker: varchar("transparency_marker", ...)`,
and `dataJurisdiction: varchar("data_jurisdiction", ...)` on the
transactions table. `apps/api/src/routes/do.ts` is the writer: it computes
`transparencyMarker: marker` and
`dataJurisdiction: getProcessingJurisdictions(capability.capabilityType, capability.transparencyTag).join(",")`
at multiple call sites (the sync, async, and x402 execution paths each
build these fields), and writes `auditTrail: audit` (and a
`failAudit` variant on the failure path) alongside them.

**The `Strale-Version` header this row specifies is live in both
directions.** `apps/api/src/lib/versioning.ts` reads the incoming
`Strale-Version` request header and writes it back on the response, and
`apps/api/src/app.ts`'s CORS configuration allows `Strale-Version` as a
request header. This matches the row's "date-based API versioning" item
exactly and CLAUDE.md's own "Date-based API versioning via
`Strale-Version` header" line.

**Both features this row specifies remain live and unmodified in
substance more than six months later**, matching the row's framing of
them as durable, low-maintenance compliance infrastructure rather than
throwaway MVP scaffolding.
