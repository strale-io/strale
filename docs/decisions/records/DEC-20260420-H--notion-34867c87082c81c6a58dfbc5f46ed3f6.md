## Decision

Of a 912-line manifest-drift audit across 275 manifests (238 Class 4
YAML/DB conflicts, 244 Class 1+2 drifts, 3 Class 5 structural gate
findings), only a narrow fix ships now: extend
`dataSourceTypeToCapType` in `onboard.ts` to accept `ai_assisted` (Class
5.2), and add a `--backfill` safety banner requiring `--force` when running
on an existing capability slug. The 238-slug Class 4 authority question
(manifest-canonical vs. split field ownership) is deferred to a future
onboarding-engine rewrite. SA.2b.c (the remaining ~260-capability PII
backfill) will use a direct-SQL path that bypasses the onboarding pipeline
entirely, avoiding both the Class 4 land mine and a second discovered risk:
`--force` executes the capability live against paid provider APIs.

## Rationale

The rationale, as the row states it: a narrow, low-risk fix now (one
mapping case plus a safety banner) closes the immediate blocker without
committing to an authority model (manifest-canonical vs. split-ownership)
that deserves full design attention at the planned Session-1 rewrite, at
the acknowledged cost of a documented "land mine" for anyone who runs
`--backfill` on a Class-4 slug before that rewrite happens.

## Consequences

Status verified on 2026-09-05, against `main`.

**The narrow fix and the safety mechanism both shipped and are present in
the codebase today**, though the codebase has moved past this row's
narrow-fix framing. `apps/api/scripts/onboard.ts` maps `case
"ai_assisted": return "ai_assisted";` exactly as this row specifies, and
carries `--force` as a documented override with console warnings guarding
`--backfill`. A newer, broader `--force-override-authority` flag also
exists in the same file ("Cluster 2 Phase 4a: --force-override-authority
interactive guard"), gated to interactive TTY sessions and refused in batch
mode: a later, stricter mechanism than this row's single `--force` flag,
not something this row itself describes.

**The deferred authority question this row parked has been resolved in
the interim, not left open through a Session-1 rewrite as planned.** All
342 manifests under `manifests/*.yaml` now declare `processes_personal_data`
(this batch's `DEC-20260420-D--notion-34867c87082c81f0827eedf29d133600`
record), and `apps/api/src/lib/audit-helpers.ts` states the heuristic
fallback was removed after migration 0050 (SA.2b.d): the specific
238-slug Class 4 drift this row named as blocking SA.2b.c was resolved by a
direct-SQL backfill path, exactly as this row's own "Path forward for
SA.2b.c" section anticipated, rather than by the deferred manifest-
authority rewrite.
