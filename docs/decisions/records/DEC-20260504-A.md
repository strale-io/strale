## Decision

Any commit that implements a cert-audit finding or adds or substantially
changes a money- or compliance-critical path must include regression coverage
for the changed path. Triggers include finding-coded commits and functions
inside wallet transactions, audit-trail builders, chain-integrity primitives,
spend-cap checks, idempotency checks, and equivalent critical paths.

The regression test must fail against the unapplied fix and pass with the fix.
When the path writes to the database, coverage must inspect bind-parameter
shapes and reject values the database encoder cannot serialize. When a catch
block intentionally swallows an error, coverage must prove the surrounding
summary or alerting path exposes the failure rather than reporting a false
healthy state.

If the relevant integration harness does not exist, a structural unit test may
pin the bug shape, but the missing harness must be named in the pull request and
Journal entry. The exemption does not apply when a suitable harness exists and
was merely skipped. Session closeout must name the covered commits and tests,
and must report any remaining test gap rather than marking it done.

## Context

PR #43 repaired a Date value passed into a SQL-template encoder in the spend-cap
path. The bug originated in cert-audit follow-up code and had silently caused
paid calls for capped users to fail. The same audit batch introduced the same
shape in retention code, where a catch block swallowed the error and emitted a
healthy-looking zero-work summary. Neither path had regression coverage.

Commit `31ca662e` and PR #44 fixed the second instance, added visibility and
database-backed test scaffolding, and introduced this protocol under the exact
`DEC-20260504-A` label. No matching Notion Decision row exists; the decision's
date, owner, active status, and global scope are derived from that introducing
commit and the current mandatory `CLAUDE.md` and `AGENTS.md` entrypoints.

## Rationale

Audit changes are often reviewed for architectural intent while missing the
runtime representation that actually failed. Requiring a test that proves both
the failing and fixed directions prevents a test from merely restating the new
implementation. Bind-shape and swallow-visibility assertions target the two
specific ways the incident remained invisible.

## Consequences

Triggered changes cannot be considered complete while their regression gap is
open. Reviews and handoffs must name the exact tests, any harness exemption,
and the evidence that the test distinguishes the fix.

This rule coexists with capability-onboarding, distribution-integrity, and
other stricter protocols. Its historical “does not override” reference to
`DEC-20260422-A` remains prose because that ID is cross-surface ambiguous and
cannot safely be a graph target. The source-gap report records the distinction.

## Reversal conditions

Supersede or amend this decision only if an alternative control gives at least
equivalent fail-before/pass-after proof for every triggered path and preserves
database-shape and swallowed-error visibility where relevant. Faster or more
convenient tests may replace a harness; removing executable regression proof
without a stronger control is not a valid reversal. Use a new decision rather
than editing this protected record in place.
