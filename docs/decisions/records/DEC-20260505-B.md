## Decision

Rip out `lifecycle.ts`'s automatic state transitions entirely (Option 1 of
three considered), retaining only the manual transition machinery.

## Context

The row's own Rationale names the trigger and the alternatives: "PR1
(commits 6e71d7d -> ae338fb, pushed 2026-05-05) deleted the SQS scoring
engine. lifecycle.ts was deeply SQS-bound: evaluateLifecycle,
runLifecycleSweep, smokeTest, getStateEnteredAt, all SQS thresholds tied to
qpScore/matrixSqs values. Three options were on the table: (Option 1) rip
out automatic transitions entirely, retain manual machinery; (Option 2)
rewrite without SQS thresholds, replace with source_health-driven
thresholds; (Option 3) freeze with feature flag for later decision. Chose
Option 1." The row states "Implements DEC-20260503-B (SQS public-score
retirement)," so `affirms DEC-20260503-B` is recorded (that record exists on
the PR head).

## Rationale

As the row states it: retained were "transitionCapability,
LifecycleState/TransitionTrigger/TransitionResult types, STATE_VISIBILITY
map, manual admin flips via lifecycle-transition.ts --slug X --to active."
Deleted were "evaluateLifecycle, runLifecycleSweep, smokeTest,
getStateEnteredAt, all SQS thresholds." The row records the accepted
post-deploy cost: "8 capabilities sit in non-active states (1 degraded, 1
probation, 6 suspended) and will not auto-recover — manual flips required,
accepted as backlog per the prepush diagnostics." It also states the
condition for revisiting: "If automatic transitions are needed in the
future, rebuild on source_health signal under a fresh DEC; do not
resurrect the SQS-threshold logic."

## Consequences

Status verified on 2026-09-05, against `main`.

**Option 1 survives exactly as chosen, with no automatic-transition
reintroduction yet.** `apps/api/src/lib/lifecycle.ts`'s own header states:
"Per DEC-20260503-B (SQS deletion), automatic transitions are removed.
Lifecycle state now only changes via: validate-capability.ts (validating ->
probation, validating -> draft); admin scripts (lifecycle-transition.ts,
batch-transition-to-probation.ts, fix-lifecycle-anomalies.ts) which call
`transitionCapability` directly; the executor onboarding pipeline (draft ->
validating after suite seeding). No background sweep evaluates SQS
thresholds. Capabilities sit in whatever state they're put in until a human
flips them." A trailing comment in the same file confirms the deletions by
name: "`evaluateLifecycle` and `runLifecycleSweep` were removed with the SQS
engine (DEC-20260503-B)... Manual flips remain via `transitionCapability`. A
future per-product routing engine may reintroduce automatic transitions
keyed on `source_health.status` once that substrate exists." Option 2's
substrate (`source_health`-driven thresholds) is named as a still-open future
path, not yet built. `apps/api/scripts/lifecycle-transition.ts` carries the
matching note: "--sweep mode was removed with the SQS engine
(DEC-20260503-B)."

**This record cannot verify whether the specific 8 capabilities named as
stuck non-active on 2026-05-05 remain in that state today**, since the row
does not name the affected slugs and no evidence file in this repository
lists them by name as of this record's writing.
