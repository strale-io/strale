## Decision

Design the Strale Quality Score (SQS): a composite 0-100 score weighting
Correctness (40%), Schema (25%), Availability (20%), Error handling
(10%), and Edge cases (5%). Upstream issues are excluded from the score
but shown as context. The same number appears everywhere. Full
methodology is published. Drill-down goes score to breakdown to test
types to individual runs. The row's own title marks it "RESOLVED, see SQS
Constitution," and its full spec was published at "Strale Quality Score
— Design Spec."

## Context

The row's stated basis, from its own Rationale: the trust display at the
time showed different numbers on different surfaces (94%, 51/54, 14/15,
3 issues), causing information overload and confusion. A single composite
score with a published methodology and drill-down was designed to
replace that.

The historical Notion scope field on this row was `global`. It is
recorded here as `scope: technical`: it specifies a scoring formula and
its weights, a technical design artifact, not a company-wide strategic or
positioning decision.

## Rationale

The rationale, as the row states it: showing different numbers on
different surfaces created confusion; one composite score, consistently
displayed with a drill-down path to the underlying test data, resolves
that directly.

## Consequences

Status verified on 2026-09-05, against `main`.

**The SQS engine this row designed was deleted, and no `/v1/quality/:slug`
endpoint exists today.** CLAUDE.md states: "SQS scoring engine deleted per
DEC-20260503-B (PR1 shipped 2026-05-05). The dual-profile model (QP + RP +
5×5 matrix), the `min_sqs` request parameter on POST /v1/do, the platform
floor SQS gate, the floor-aware solution SQS rule, the public
`/v1/quality/:slug` endpoint, and the automatic lifecycle transitions...
are all gone." A search of `apps/api/src/routes` for `quality/:slug` or
`v1/quality` found no match, confirming the endpoint is gone in code, not
only in the CLAUDE.md description.

**What survives:** circuit-breaker logic on `capability_health`
(`apps/api/src/db/schema.ts` line 964 comments the table
`capability_health (circuit breaker)`, and the table itself is defined at
line 966), plus fixture and canary test modes, per the same CLAUDE.md
paragraph. Quality signals today come from production observability,
piggyback test suites, and zero-cost auth-less probes where a vendor
permits one, not from the composite SQS score this row designed.

**The row's own title cites "SQS Constitution" as the resolving artifact,
but the record with that exact name does not exist under this historical
ID.** CLAUDE.md's "Current Decisions (March 2026)" section names
"DEC-20260307: SQS Constitution adopted as authoritative scoring spec" —
a distinct historical ID (`DEC-20260307`) from `DEC-20260308-1`. This
batch's brief anticipated a possible link to `DEC-20260308-1`; verifying
its actual formal record shows its title is "Platform pricing currency:
EUR (not USD)," an unrelated subject, not the SQS Constitution. No formal
record exists for `DEC-20260307` in this repository, so no `related_to`
edge is created here: per this batch's rule, an edge may only target a
record that exists on the PR head, and the record that would be the
