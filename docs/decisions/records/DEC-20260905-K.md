## Decision

The quotation convention for this candidate set is unchanged from
`DEC-20260905-J`: normalize quotation and source before comparing:
transliterate `€` to `EUR`, `×` to `x`, `≥` to `>=`, `≤` to `<=`, `→` to
`->`, `…` to `...`; lowercase; delete every character that is not a
letter or digit. A quotation is faithful when its normalized form is a
substring of the normalized source (an ellipsis splits it into ordered
segments). Punctuation, dashes, quote marks, case, markdown emphasis,
whitespace and the punctuation at a truncation point are therefore never
defects. Defects are: a word inserted, dropped, replaced or reordered; a
composite presented as one quotation; a quotation whose named source does
not contain it (wrong file, function, document, record or row field); a
quotation attributed to a source outside the repository, the parsed row,
the sibling frontend checkout or a merged pull request; and any false
statement about repository state at the commit. The relation rule is
also unchanged: a relation declared in a record's frontmatter whose basis
is stated in an amending record, or narrated in the target record's own
body, is substantiated; the narration need not live in the source
record's own body once that basis is stated somewhere reachable from the
record. `DEC-20260905-I`'s dated-observation clause (a figure a record
states as of a date is not a defect merely because unrelated work later
moves it, and an amending record's affirmation of it that was true at
that record's own commit is not a wrong correction) carries forward
unchanged. `DEC-20260905-J`'s statute clause (a quotation of a published
statute or regulation that the sentence names by instrument and article
is verifiable against that public instrument and is not an unverifiable
source; it is checked against the statute's own text, which lives
outside this repository by design, and is Not adopted under this clause
rather than withdrawn as unverifiable) also carries forward unchanged.

The statements listed below are withdrawn from `DEC-20260905-J` and
replaced by the facts stated here. A fifth item substantiates, without
withdrawing anything, that two named-source sweep entries this record's
review re-checked were already withdrawn by earlier items before
`DEC-20260905-J` merged.

## Context

`DEC-20260905-J` merged at commit `2801a08f` before a correction commit
that fixed its own item-count arithmetic reached its branch: the
correction was written after the branch's auto-merge had already fired,
so it never landed. Active records are immutable
(`DECISION_ACTIVE_BODY_CHANGED`), so the fix cannot be an edit to
`DEC-20260905-J.md`; it is this record instead, the same mechanism every
prior round in this chain used to correct a merged predecessor. The
session handoff file for round 9,
`handoff/_general/from-code/2026-09-06-t10-g9-closing-review-round-9.md`,
carries the same slipped arithmetic in its own summary counts; this
record's own PR adds a further handoff file,
`handoff/_general/from-code/2026-09-06-t10-g9-closing-review-round-9b.md`,
that restates the corrected counts. The round-9 handoff file itself is
not edited, for the same immutability reason a merged record is not.

## Rationale

A record whose subject is counting another record's own items must
itself count correctly. A correction that misses the merge window is
handled the same way any other post-merge correction in this chain is:
a new record, never an edit to the merged one.
