## Consequences

Status verified on 2026-09-05, against `main`.

**The row's Decision statement was false when it was made, by the repo's
own later comment, and remains false today: `test-runner.ts` never calls
`recordFailure`.** `apps/api/src/lib/circuit-breaker.ts`'s own header
comment for `PLATFORM_REFUSAL_PATTERNS` states this directly: "Until now
nothing routed them here: `test-runner.ts` never called `recordFailure`,
which is what made them inert (and what the cost-control accounting tests
rely on)." A repository-wide search for `recordFailure(` calls
(`apps/api/src`, excluding test files) finds exactly four call sites, all in
`apps/api/src/routes/do.ts` (the customer-facing `/v1/do` path), and none in
`test-runner.ts`. `test-runner.ts` instead calls `recordTestEvidence` (a
different, evidence-only function in `circuit-breaker.ts`) on a passing
test, and explicitly declines to call `recordFailure` on a failing one; its
own comment states why: "Phase 3 Harden Fix B — feeding test failures into
the circuit breaker — is deliberately NOT wired here... The breaker is a
customer-facing, immediate actuator and should be driven by customer
traffic. Test signal already has one built for it — the quality floor
(DEC-20260812-A), with a >=10-real-call minimum, thresholds, dry-run and
reversibility. Route it there instead."

**The platform-refusal breaker test file confirms the same boundary from
the opposite direction: what counts as a failure is deliberately narrowed,
not widened, since this row was written.** `platform-refusal-breaker.test.ts`
exists to assert that platform-issued refusals (a dispatcher gate declining
non-customer credit spend, an unclassified capability failing closed, an
exhausted test budget) do not trip the breaker; `circuit-breaker.ts`'s own
comment states the reason a fix was needed at all: "Without this guard,
every paid capability's scheduled test would trip its own breaker and
suspend it for real customers: 91 such refusals across 8 capabilities in the
last 30 days." So the repository's actual history moved in the opposite
direction from this row's stated Decision: instead of wiring test failures
into `capability_health`, the codebase built a guard to keep platform
refusals (which a naive test-signal wiring would have misclassified as
failures) from tripping the breaker at all, and routed real test-derived
quality signal to a separate mechanism (the quality floor, `DEC-20260812-A`)
rather than the circuit breaker `capability_health` governs.
