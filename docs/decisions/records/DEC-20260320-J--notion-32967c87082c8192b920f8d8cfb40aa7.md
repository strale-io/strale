## Decision

`pep-check` uses the transparency tag `mixed` instead of
`commercial_data`.

## Context

The row's stated basis, from its own Rationale: `commercial_data` is not
a valid `transparency_tag` in the codebase. Claude Code used `mixed`
instead during implementation. The row notes the KYB spec (v5) should be
updated to reflect this.

This historical ID is reused by a second, unrelated Notion row (the
dynamic-methodology-counts rule, made the same day) and was an
unresolved registry collision until this batch; the two rows are
resolved together in
`archive/sessions/2026-09-05-decision-collision-resolution-DEC-20260320-J.md`
with distinct source-qualified record keys. This record covers only the
pep-check transparency-tag row.

The historical Notion scope field on this row was `feature`. It is
recorded here as `scope: technical`: it is a manifest-field
implementation choice for one capability.

## Rationale

The rationale, as the row states it: `commercial_data` was not an
accepted enum value in the codebase's transparency-tag vocabulary, so
`mixed` was substituted as the nearest valid tag rather than blocking
onboarding on a spec correction.

## Consequences

Status verified on 2026-09-05, against `main`. **The row's stated
substitution is not what ships today.** `manifests/pep-check.yaml`
declares `transparency_tag: algorithmic`, not `mixed`, and not
`commercial_data`. This record cannot determine from the repository
alone when or why the tag changed from `mixed` to `algorithmic` between
this row's decision date and today; no commit message or later decision
record naming that specific change was found in this batch's search.
CLAUDE.md's capability list independently states "`pep-check` —
... Transparency: algorithmic," consistent with the manifest and with
neither of the row's two named values.

## Reversal conditions

None recorded on the row (`Superseded By` is null in the source). The
Consequences above record that the tag in production today differs from
both values this row discusses; a future decision documenting the
change to `algorithmic` would be the natural successor record, not yet
present.
