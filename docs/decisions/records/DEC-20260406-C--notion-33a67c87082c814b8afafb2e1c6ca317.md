## Decision

Physically tidy the Notion Project Home: keep a canonical set of pages at the
top level and archive roughly 90 non-canonical sibling pages to an Archive
area, dated Q1 2026.

## Context

The row's own Rationale states the basis directly: "Operating Manual
(DEC-20260406-B) established the governance layer. This decision executes
the content-layer tidy that the governance layer requires. The pre-tidy
state had Failure Mode 2 (supersession without archival) re-emerging within
30 days of the prior governance protocol, fixing it was urgent because a
governance layer not backed by a tidy content layer loses credibility fast.
The tidy also unblocks Phase 3 content consolidation, which cannot proceed
cleanly while ~90 non-canonical siblings obscure the canonical set."

This historical ID is reused by a second, unrelated Notion row (Rule E,
brand-voice institutional writing) made the same day and was an unresolved
registry collision until this batch; the two rows are resolved together in
`archive/sessions/2026-09-05-decision-collision-resolution-DEC-20260406-C.md`
with distinct source-qualified record keys. This record covers only the
Project Home tidy row.

The historical Notion scope field on this row was `global`. It is recorded
here as `scope: product`: it is a Notion-workspace content-organization
decision, not a technical implementation.

## Rationale

The rationale, as the row states it: a governance protocol (DEC-20260406-B's
Operating Manual) is only credible if the content layer it governs is
actually tidy; the recent recurrence of "supersession without archival"
within 30 days of that protocol's own adoption made the tidy urgent, and
completing it unblocks the Phase 3 content consolidation that depends on a
clean canonical set.

## Consequences

Status verified on 2026-09-05, against `main`.

**This is a Notion-workspace state, not a repo-tracked artefact, and this
repository's pre-cutover posture leaves it untouched by design.**
CLAUDE.md's "Repo-native migration continuation — pre-cutover" section
states this explicitly: "Candidate project documents remain inactive and
Notion-backed workflows remain authoritative until the explicit atomic

names M4 as the cutover milestone. No file in this repository can confirm

Whether that CLAUDE.md section is a live restatement of this row's
