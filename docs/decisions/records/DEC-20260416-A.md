## Decision

`strale-mcp` and x402/Bazaar are complementary, not competing: developer
audience versus runtime audience.

## Context

The historical Notion scope field on this row was `global`. It is recorded
here as `scope: product` under this repository's decision-record
vocabulary: this decision is a positioning call about how two distribution
surfaces relate, not a rail-mechanics choice. The row's own `Source` field
cites a further Notion page (`34267c87082c81778568e9606826b243`), not one
of this batch's six target rows and not read for this record.

## Rationale

Two orthogonal audiences: `strale-mcp` serves developers at integration
time (API key, prepaid wallet, full SQS/provenance metadata, distributed
via Claude Desktop, Cursor, Windsurf, VS Code, and ChatGPT connectors). x402
on Base mainnet (including Bazaar MCP) serves autonomous agents at runtime
(no signup, USDC pay-per-call). The wallet is strictly better for
known-volume users (no per-transaction USDC plus gas); the first-party MCP
is the only surface that exposes Strale's differentiated metadata (SQS,
limitations, structured errors). Deprecating `strale-mcp` would gut the
integrations-page activation flow and commoditize Strale behind Bazaar's
wrapper. A curated Bazaar wrapper (the rejected third option) would add
maintenance for marginal benefit over Bazaar's native discovery. Keep both,
position explicitly.

## Consequences

Status verified on 2026-09-04, against `main`.

**Both surfaces this row named exist today, and the audience split still
holds structurally.** `packages/mcp-server/` still ships `strale-mcp` as a
first-party package. `apps/api/src/routes/x402-gateway-v2.ts` implements a
"Bazaar discovery extension builder" (`toBazaarFields`,
`buildBazaarDiscovery`) that emits Bazaar-format field descriptors for
paid capability routes, and CLAUDE.md's "x402 Payment Gateway (March
2026)" paragraph confirms x402 requires no signup or API key — "payment IS
the auth" — the runtime-audience half of this row's split, unchanged since
this row was decided.

**The quality-metadata claim this row makes for `strale-mcp` — "full
SQS/provenance metadata" — is partly stale.** The SQS engine this row
refers to was deleted on 2026-05-05 (DEC-20260503-B; CLAUDE.md's "SQS
scoring engine deleted" paragraph). Provenance metadata (data source,
fetch timestamp) survives per capability response, but the numeric SQS
score `strale-mcp` exposed at the time this row was decided no longer
exists to expose. This does not change the audience-split argument this
row makes (developer-time integration versus runtime pay-per-call remains
the real distinction), but the specific evidence cited for MCP's
differentiation — SQS — has since been retired.

**A later incident on the `strale-mcp` side of this split bears directly on
the "the first-party MCP is the only surface that exposes Strale's
differentiated metadata" claim.** CLAUDE.md's Distribution PR Integrity
Protocol records that on 2026-08-23 a production contract smoke test found
`strale-mcp` had shipped `0 cap trust, 0 sol trust` for roughly 3.5 months:
the trust routes this row's differentiation depended on were deleted in
May 2026, the admin wall on their prefix answered 401 instead of 404, and
the client logged the degradation to invisible stderr and carried on.
Postdating both this row (2026-04-16) and DEC-20260313-F (2026-03-13), the
incident means the differentiated-metadata claim this row and DEC-20260313-F
both rest on was not actually true in production for most of the interval
between them; the structural fix (the post-publish production contract
smoke test, `docs/release/npm-publishing.md`) is now in place.

## Reversal conditions

Reconsider this decision if x402/Bazaar's runtime audience begins
demanding the same differentiated metadata `strale-mcp` provides, if
`strale-mcp`'s integration-time value proposition is undermined by a
further trust-metadata gap, or if Bazaar's native discovery makes a
curated wrapper worthwhile after all. Represent a change of this decision
through a new decision rather than editing this protected record in place.
