## Decision

Use Dilisense as the single upstream for the then-current sanctions and PEP
screening path instead of an OpenSanctions-primary/Dilisense-fallback design.
Preserve honest source attribution and null values where Dilisense does not
expose per-list versions, timestamps, match scores, or topic depth.

Adverse media remains a separate shape: Dilisense is primary and the Serper
search path remains a fallback. `DEC-20260427-A` governs disclosure of the
measured native-language limitation.

## Context

Production had no OpenSanctions API key configured, so the apparent dual path
was already falling through to Dilisense. The April empirical battery recorded
complete hits for the selected prominent-PEP sample and functional sanctions
matching through Dilisense, while the OpenSanctions trial had expired and
commercial use required further licensing and cost evidence.

The source compared configuring a paid OpenSanctions path, simplifying to
Dilisense, and replacing both vendors. It chose the already observed Dilisense
path for the launch-era product and deleted the unused OpenSanctions catalog
code.

## Rationale

For the tested use case, the marginal audit detail attributed to OpenSanctions
did not justify another contract, processor, failure path, and commercial
licence. Dilisense's omissions could be stated explicitly rather than filled
with invented precision. A simpler architecture also made the actual data path
match the reported provenance.

The source's sample, source counts, prices, uptime claim, and product vocabulary
are dated observations. They are not permanent coverage, licensing, or
commercial facts.

## Consequences

Sanctions and PEP became unavailable when Dilisense was unavailable; no hidden
OpenSanctions fallback remained. The response retained named-source attribution
but could not provide data Dilisense did not expose. Current
`platform-facts.ts`, manifests, executors, dependency data, and live account
state must be checked before relying on that architecture today.

`DEC-20260429-A` later corrected the commercial-licence premise behind a
self-host roadmap and deferred that path. This record does not invent a graph
edge because the later source did not formally name this Decision. It also does
not authorize a current contract or claim that any historical price or plan is
still available.

## Reversal conditions

Reopen the technical choice if verified customer requirements demand dataset
version replay or audit detail the current source cannot supply, current
coverage testing reveals material gaps, reliability materially degrades, or a
lawfully licensable alternative demonstrates better quality and economics.
Vendor contact, account creation, terms, licensing, commitments, and external
claims remain separately `approval_required`.
