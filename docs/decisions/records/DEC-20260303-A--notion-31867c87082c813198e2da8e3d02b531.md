## Decision

The homepage's Problem→Solution section uses SVG architecture diagrams
plus bullet lists, not code blocks.

## Context

The row's stated basis, from its own Rationale: the section went through
three iterations. Code blocks duplicated the hero section's code example;
a result card duplicated the hero's output display. The final approach
uses SVG architecture diagrams for visual contrast (a tangled multicolor
diagram versus a clean green one) with scannable bullet lists: left-side
bullets cover pain points, right-side bullets cover benefits, all items
audited against every other section on the page to eliminate
duplication. The row states the diagrams communicate
complexity-versus-simplicity faster than text or code could.

This historical ID is reused by a second, unrelated Notion row (a
solution-discovery smart-input UX decision made the same day) and was an
unresolved registry collision until this batch; the two rows are
resolved together in
`archive/sessions/2026-09-05-decision-collision-resolution-DEC-20260303-A.md`
with distinct source-qualified record keys. This record covers only the
Problem→Solution SVG-diagram row.

## Rationale

The rationale, as the row states it: duplicating the hero's code example
or output display in a second section wastes a viewport without adding
information; SVG diagrams contrasting "tangled" (today's DIY integration
work) against "clean" (Strale) communicate the problem/solution gap
visually, faster than a reader would parse equivalent prose or code.

## Consequences

Status verified on 2026-09-05, against the sibling `strale-frontend`
checkout, read-only.

**The section still uses diagrams and bullet lists, not code blocks.**
`strale-io/strale-frontend@04c9fca9:src/components/ProblemSection.tsx`
imports `TodayDiagram` and `StraleDiagram` from
`src/components/problem/`, alongside a `VerdictChips` component, and
defines two bullet-chip arrays: `painChips` ("5× auth keys", "5× response
schemas", "custom retry logic", "DIY audit trail", "silent failures at
2am") and `benefitChips` ("one API key", "consistent JSON", "retries
built in", "audit trail on every call", "MCP + A2A discovery"). No
`<pre>`, `<code>`, or syntax-highlighted code block appears in this
component.

**The two-diagram, contrast structure matches the row's description**:
one diagram represents the pre-Strale state (`TodayDiagram`), the other
the Strale state (`StraleDiagram`), consistent with the row's
"tangled multicolor vs clean green" pairing, though the exact colour
treatment was not independently re-verified pixel-by-pixel by this
record.

This verification did not re-audit every bullet against every other
homepage section for duplication, as the row's own process describes
doing at the time; it confirms only that the committed component today
still follows the diagrams-plus-bullets structure, not code blocks.

## Reversal conditions

None recorded on the row (`Superseded By` and `Outcome` are both null in
the source). A future redesign of the Problem→Solution section
reintroducing code blocks, or restructuring it around a different
visual pattern, would supersede this row.
