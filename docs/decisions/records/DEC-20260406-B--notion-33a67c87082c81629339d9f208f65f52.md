## Decision

Restructure the Notion workspace around an Operating Manual page as the
single entry point, organized under a four-layer model: canonical pages
/ databases / archives / not-Strale.

## Context

The row's stated basis, from its own Rationale: the prior Notion
Governance Protocol (2026-03-07) established good rules but drifted
badly over four weeks. Diagnosis identified four failure modes: (1)
rules were not enforced at creation time because Claude was not told to
check before creating; (2) supersession did not include archival, so
SUPERSEDED-prefixed pages remained in the main list; (3) the single
to-do list was a page rather than a database and decayed; (4) an audit
flagged 11 pages for archival that were never actually moved. The
restructure establishes: (a) an Operating Manual page
(`33a67c87-082c-8173801fce3f3ba565b6`) as the single entry point every
assistant reads before creating anything; (b) the four-layer model
(canonical pages / databases / archives / not-Strale); (c) a To-do
database replacing the Roadmap page as the ledger for active work
(created in the Notion UI, since it could not be created via MCP); (d)
the Journal DB taking on the brainstorm role via its existing brainstorm
type rather than a parallel Brainstorms DB; (e) the Feature Registry
retained as the backing DB for the Product Roadmap canonical page; (f)
Deferred retained as an icebox, related to the new To-do DB; (g) 15
canonical pages listed in the Operating Manual's directory, most
pointing at existing pages rather than creating parallel shells (only 3
genuinely new shells: Operating Manual, Value Proposition, Data
Providers and Contacts). Content migration and page promotion were
deferred to Phase 3 across future sessions.

This historical ID is reused by a second, unrelated Notion row (the fix
for nested field reference resolution in solution input mapping, made
the day before) and was an unresolved registry collision until this
batch; the two rows are resolved together in
`archive/sessions/2026-09-05-decision-collision-resolution-DEC-20260406-B.md`
with distinct source-qualified record keys. This record covers only the
Notion-restructure row.

## Rationale

The rationale, as the row states it: the prior governance protocol
failed on enforcement-at-creation, archival-on-supersession, ledger
decay (a page instead of a database), and audit follow-through; a single
entry-point page with a four-layer model and a proper To-do database
targets each named failure mode directly.

## Consequences

Status verified on 2026-09-05, against `main`. CLAUDE.md and the repo's
current governance surfaces show a different current structure, not
this row's four-layer / Operating Manual model.

**CLAUDE.md's current Notion Workspace Structure section describes an
8-section layout, not this row's four-layer model.** CLAUDE.md's
"Notion Workspace Structure (8 sections under Project Home)" lists 🏠
Start Here, 🎯 Strategy, 🛠️ Products, ✅ To-do & Build Plan, 📣 Go-to-
market, 🔧 Internals, 📓 Journal, and ⚙️ How we work. It does not name
an "Operating Manual" page, and its organizing principle (8 numbered
sections under one Project Home) is a different shape from this row's
"four-layer model: canonical pages / databases / archives / not-Strale."
This record cannot determine from the repository alone whether the
8-section structure supersedes the row's restructure, coexists with it
inside Notion, or reflects a still-later reorganization; CLAUDE.md is
this repository's only readable trace of Notion's structure.

**Operating governance has since moved substantially into the
repository itself, a shift this row's Notion-only restructure did not
anticipate.** `docs/company/CHARTER.md` (DEC-20260815-A) states it
governs "day-to-day operation" and amends a later escalation contract
directly in a repo file; `docs/programs/README.md` states "Programs are
execution records, not project truth... Project truth lives in
`docs/project/` (candidate until M4) and `docs/decisions/`." Both
postdate this row by more than four months and describe a canonical-
page-in-a-repo-file model this row's Notion-page restructure does not
mention. This record treats the two as a later, larger reorganization of
where operating truth lives, not evidence against this row's own Notion
restructure having happened as described.
