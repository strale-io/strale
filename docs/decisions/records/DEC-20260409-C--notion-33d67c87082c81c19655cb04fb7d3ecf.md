## Decision

Every solution runs end-to-end against a canonical test input on its own
test cycle, independent of its constituent capabilities' individual tests.
Each solution declares a `canonical_test_input` block in its definition.
Results feed a new solution-level Reliability Profile factor, displayed
alongside (not replacing) the existing floor-aware weighted average from
capability scores. Cadence matches the solution's existing adaptive
scheduler tier (probation 6h, normal 24h, established 72h), managed for
cost because solution smoke tests re-execute every constituent capability.

## Context

The row's own Rationale states the basis: solutions are compositions with
their own input-mapping and step-chaining layer, so individual capability
tests can pass while the composition fails end-to-end. It cites the
SpendLatch `kyb-complete-de` incident: "all 12 constituent capabilities had
clean SQS scores, but the solution was broken end-to-end due to input
mapping bugs." Gate 1 (the solution input-mapping validator, onboarding-time)
catches static bugs; this decision's Gate 4 catches runtime composition
failures continuously. The row estimates cost at "€2.50 × 100 solutions ×
daily cadence = ~€250/day if all run every 24h" absent adaptive scheduling,
and names this the "final gate from the SpendLatch incident," closing the
Phase 3 hardening lineage alongside Gate 1 through Gate 3 (`RELATED:
DEC-20260409-A` for Gate 2, `DEC-20260409-B` for code-based lookup and
cross-validation).

## Rationale

The rationale, as the row states it: static analysis alone cannot catch
runtime composition failures, and the SpendLatch incident showed real
customer cost from relying only on capability-level scores; continuous
solution-level smoke testing closes that gap at a cost bounded by adaptive
scheduling rather than a flat daily-for-every-solution cadence.
