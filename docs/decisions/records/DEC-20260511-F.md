## Decision

Investigate and restore the daily-digest pipeline, which has not produced a
successful run since 2026-04-14.

## Context

The row's own Rationale states the finding: "The daily-digest pipeline
(apps/api/src/jobs/daily-digest.ts → Resend → petter@strale.io) has not
produced a successful run since 2026-04-14. digest_snapshots table is empty
for 27 days; Petter confirmed no digest emails received in that window...
Surfaced as a side-effect of DEC-20260511-E pre-flight: the digest was the
original surface candidate; verifying its delivery surfaced the gap.
Confidence: high on diagnosis (snapshot table is empty, Petter confirms no
email); medium on the recommended fix (depends on root cause — cron not
firing vs. pipeline throwing before saveSnapshot vs. Resend send failing)."
The row names `DEC-20260511-E` as the investigation that surfaced this gap;
that record exists on the PR head, but the sentence names it as the origin
of the finding, not as a target this row itself amends, affirms, or
supersedes, so no relation edge is recorded here (the reciprocal citation is
recorded on `DEC-20260511-E`'s own record).

## Rationale

As the row states it: the diagnosis is high-confidence (an empty
`digest_snapshots` table for 27 days, and Petter's own confirmation of no
received email), while the recommended fix is only medium-confidence
because the root cause was, at the time of writing, still one of three
candidates: the cron never firing, the pipeline throwing before
`saveSnapshot`, or Resend's send call failing silently.

## Consequences

Status verified on 2026-09-05, against `main`.

**The pipeline exists and can run today, but this record finds no evidence
of an automated schedule that fires it; the gap this row found may never
have been closed at the "restoration" the row's own title claims, only
diagnosed.** `apps/api/src/jobs/daily-digest.ts`'s own header states its
invocation model plainly: "Usage: cd apps/api && npx tsx
src/jobs/daily-digest.ts," a manual command, not a scheduled job. A
repository-wide search for a cron trigger or scheduled workflow invoking it
finds none in `.github/workflows/`; `apps/api/src/jobs/test-scheduler.ts`'s
own comment names the reason: "Weekly digest scheduling lived in the
deleted block of test-runner.ts. The digest itself still works via the
daily-digest pipeline; this explicit Monday-08:00 timer is gone until
re-introduced." `apps/api/package.json` exposes it as an npm script
(`"digest": "tsx src/jobs/daily-digest.ts"`), and
`apps/api/src/routes/admin.ts` exposes `POST /v1/admin/digest` ("Trigger
digest email now") which runs the same gather/analyze/render/send/snapshot
sequence on demand. Both are manual triggers; this record found no
in-process timer or external cron wired to either.

**The existing record for `DEC-20260317-A` (the row that originally set the
weekly-digest-plus-interrupt model this pipeline implements) independently
verified the same silence and reached the same "unwired" finding for the
interrupt half of the model, and quotes this row's own Rationale text
directly.** That record states: "A later, unmigrated row, DEC-20260511-F
(Status: active, prose only, not a formal record and not part of this
batch), states: 'The daily-digest pipeline
(apps/api/src/jobs/daily-digest.ts -> Resend -> petter@strale.io) has not
produced a successful run since 2026-04-14...' No cron trigger or scheduled
workflow for daily-digest.ts was found in this repository." This record's
own independent check (above) confirms the same absence still holds as of
2026-09-05, and additionally finds no interrupt-path caller: `interrupt-sender.ts`'s
exported `sendInterruptEmail` still has zero callers anywhere in
`apps/api/src` outside its own definition file.
