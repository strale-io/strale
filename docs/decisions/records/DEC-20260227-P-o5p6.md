## Decision

Updated provider growth sequencing: Phase 0 now, Phase 1 at month 2,
Phase 2 at months 3-4, Phase 3 at months 5-6.

## Context

The row's title carries the whole decision; its Rationale supplies the
substance. The original plan was Phase 0 (months 1-3) equals 5
capabilities. The new plan: Phase 0 (now) equals 200+ capabilities,
launching with the full catalog. Phase 1 (month 2): demand signals go
public, a Wrapper CLI ships, and 3-5 MCP server authors are recruited.
Phase 2 (months 3-4): the provider-lite model per `DEC-g9h0`, Stripe
Connect, manual review, and 10-20 providers. Phase 3 (months 5-6): open
registration, automated review, and 50+ providers.

The historical Notion scope field on this row was `global` in the
workspace's old vocabulary. It is recorded here as `scope: product`: this
is a roadmap-sequencing decision, not a single technical integration.

**Relation to `DEC-20260227-P-a1b2`.** This row's Rationale explicitly
names "Original: Phase 0 (months 1-3) = 5 capabilities. New: Phase 0
(now) = 200+ capabilities," the exact acceleration `a1b2` decided; this
row `amends` `a1b2` by restating and extending its Phase 0 change into a
full four-phase sequence.

**Relation to `DEC-20260225-P-g9h0`.** This row's Rationale names the
earlier row directly: "Phase 2 (month 3-4) = provider-lite model per
DEC-g9h0, Stripe Connect, manual review, 10-20 providers." This is a
literal source-stated reference to `DEC-20260225-P-g9h0` (the row
proposing the provider-lite contractor model), so this row is recorded as
`related_to` it.

## Rationale

The rationale, as the row states it: the original three-month, 5-capability
Phase 0 plan is replaced with an immediate, full-catalog Phase 0, pushing
every subsequent phase (public demand signals and a CLI at month 2,
provider-lite recruitment and Stripe Connect at months 3-4, open
registration at months 5-6) forward on the same accelerated timeline.

## Consequences

Status verified on 2026-09-05, against `main`.

**Phase 0's capability-count target was met and exceeded; every later
phase's provider-recruitment content was not executed.** `ls
manifests/*.yaml | wc -l` returns 342 manifests on `main` (dated
2026-09-05), well past the 200+ target. `DEC-20260225-P-g9h0`'s
Consequences establish that no third-party provider, contractor or
otherwise, has ever been onboarded; that finding applies directly to this
row's Phase 1 ("recruit 3-5 MCP server authors"), Phase 2 ("provider-lite
model... 10-20 providers"), and Phase 3 ("open registration... 50+
providers") targets, none of which this verification found evidence of
having been executed.

**Stripe Connect, named in this row's Phase 2, remains explicitly off.**
CLAUDE.md's Tech Stack states "Payments: Stripe Checkout (wallet top-ups
only, no Connect)," unchanged from this row's implicit assumption that
Connect would be turned on by months 3-4 to support paying third-party
providers.

**No "Wrapper CLI" was found as a shipped or documented artifact.** A
search of `packages/` and `docs/` for a CLI wrapper tool matching this
row's Phase 1 item found no match; this item, like the provider-count
targets, does not appear to have been built.

## Reversal conditions

None recorded on the row (`Superseded By` and `Outcome` are both null in
the source). The capability-count half of Phase 0 succeeded and was
exceeded; the provider-recruitment content of every later phase was not
executed and no later record was found formally abandoning it.
