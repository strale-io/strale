## Decision

Adopt a seven-color data/accent palette for strale.dev's dark mode: blue
`#6BA1E2`, purple `#A18CDC`, pink `#DF7FAE`, yellow `#D1BC75` (anchor),
orange `#E2A343`, red `#E17979`, green `#74C99D`.

## Context

The row's stated basis, from its own Rationale: "strale.dev had no
chart/visualization palette. Components used raw Tailwind classes
(text-green-500 etc.) that clashed with the muted editorial aesthetic.
New palette: blue #6BA1E2, purple #A18CDC, pink #DF7FAE, yellow #D1BC75
(anchor), orange #E2A343, red #E17979, green #74C99D. All WCAG AA+ on
#0D0D0E. 50/50 midpoint between vibrant and muted variants. CSS vars:
--color-{name}. Tailwind: accent-{name}."

The historical Notion scope field on this row was `global`. It is
recorded here as `scope: product`: it is a specific visual-design
palette decision for one surface, not a company-wide strategic decision.
The row's own text does not name any other Decision ID, so no relation
edge is recorded here.

## Rationale

The rationale, as the row states it: the site had no dedicated
chart/accent palette and was leaning on raw Tailwind color utilities
that clashed with the site's muted editorial look; the seven listed
hex values were chosen as a 50/50 midpoint between vibrant and muted
variants, each verified WCAG AA+ against a `#0D0D0E` background, with
yellow as the anchor color and a `--color-{name}` / `accent-{name}`
naming convention for CSS variables and Tailwind classes respectively.

## Consequences

Status verified on 2026-09-05, against `main`.

**Under DEC-20260902-A, design values now live in `design/tokens/`, and
this palette is not there.** `design/tokens/active.json` (this
repository's canonical, per-surface design-token source per
`docs/company/DESIGN-SYSTEM.md`) contains no `#6BA1E2`, `#A18CDC`,
`#DF7FAE`, `#D1BC75`, `#E2A343`, `#E17979`, or `#74C99D` anywhere
(checked directly against the file); its only "accent" entries are a
single light-mode `"accent": "#2563EB"` value and unrelated dark
sidebar-accent HSL tokens, not a seven-member chart palette. Neither
`design/tokens/candidates/codex-handoff-round-23.json` nor
`design/tokens/candidates/quiet-material-v0.7.json` contains these
values either.

**The old frontend repository does not carry this palette verbatim
either, and uses a different naming convention than the row specifies.**
`strale-io/strale-frontend@04c9fca9:src/index.css` defines CSS custom properties
`--pink` (`330 59% 69%`), `--purple` (`262 42% 70%`), `--info`
(`262 42% 70%`), `--success` (`149 39% 62%`), `--warning` (`36 73% 57%`),
`--teal` (`149 39% 62%`), and `--destructive` (`0 65% 68%`), stored as
HSL triples rather than the hex values the row specifies, and named by
semantic role (`--success`, `--warning`, `--info`, `--destructive`)
rather than by color name with the row's own `--color-{name}` prefix.
No `--color-blue`, `--color-purple`, `--color-pink`, `--color-yellow`,
`--color-orange`, `--color-red`, or `--color-green` variable exists, and
no `accent-{name}` Tailwind utility class of the kind the row specifies
was found. Whether these HSL values are a renamed descendant of the
row's palette, or an unrelated, earlier or later color system, is not
established by this record; only that the exact naming convention and
hex values the row specifies do not exist in either repository today.
