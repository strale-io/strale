## Decision

Lock three Evidence Tiers, distinct from the Vendor Roster Data Sourcing
Tier system (which keeps its existing semantics), with required field
lists per tier:

- **Evidence Tier 1 — Identity** (mandatory hard guarantee): `legal_name`,
  `primary_registration_id`, `status` (normalised), `legal_form` (ISO 20275
  ELF), `registered_address`, `date_incorporated`. If Strale cannot return
  Tier 1, the call returns `insufficient_evidence` and is not charged.
- **Evidence Tier 2 — Bindability** (per-country availability flag):
  `legal_representatives[]` with role-normalised entries, `signing_authority`
  where the registry surfaces it. Explicit "not exposed by this registry"
  rather than silence.
- **Evidence Tier 3 — Ownership disclosure** (availability flag mandatory,
  data conditional): `ubo_availability` flag ALWAYS returned (one of:
  `available` / `restricted` / `unavailable_no_registry`);
  `shareholders[]` and `ubo[]` returned where accessible. Silence on UBO is
  unacceptable.

Documents (trade register extracts, articles of association, financial
statements) are NOT Evidence Tier 4. They are a separate product dimension,
deferred to v1.1 as a priced upsell. The Evidence Tier framework stops at
Tier 3.

Disambiguation: "Evidence Tier" (this decision) and "Data Sourcing Tier"
(the Vendor Roster Doctrine fit enum: Tier 1 Strale-built / Tier 2
vendor-mediated / Tier 3 licensed bulk) are distinct systems with
non-overlapping semantics. Doctrine pages must use the full term "Evidence
Tier" or "Data Sourcing Tier" to avoid conflation.

## Context

A customer-contract gap surfaced in a 2026-05-18 chat session. The
Counterparty Assurance product page had section-level output structure
(Entity / Sanctions / Ownership / Bank / Decision-readiness) but no
field-level output contract. A test-chat audit of EU30 business-registry
coverage attempted to produce a Tier 1-4 framework because no canonical
existed — a silent-translation surface where a chat-invented framework
would be reinvented differently by the next chat, at the level of a
customer promise.

The historical Notion scope field on this row was `global`. It is recorded
here as `scope: product` under this repository's decision-record
vocabulary: this decision defines the customer-facing data contract for a
product.

## Rationale

Locking the field-level contract before the next audit runs prevents each
session from silently inventing its own tier vocabulary, and gives
`insufficient_evidence` and `ubo_availability` explicit, enforceable
semantics rather than ad hoc per-country judgment calls.

## Consequences

Status on 2026-09-04, verified against `main`.

**`ubo_availability` is live and widely implemented, exactly as this row's
Tier 3 clause specifies.** It appears in company-data executors for
roughly thirty countries under `apps/api/src/capabilities/` (Austria,
Belgium, Bulgaria, Canada, Croatia, Cyprus, Czechia, Denmark, Netherlands,
Estonia, Finland, France, Germany, Greece, Hungary, Ireland, Italy,
Latvia, Lithuania, Luxembourg, Malta, Norway, Poland, Portugal, Romania,
Singapore, Slovakia, Slovenia, Spain, Sweden, UK, and the US Cobalt
capability), using the three-value enum this row specifies. For example
`apps/api/src/capabilities/uk-company-data.ts` sets
`o.ubo_availability = "available"` with "Beneficial ownership data
available via UK PSC register," and
`apps/api/src/capabilities/danish-company-data.ts` sets
`o.ubo_availability = "unavailable_no_registry"` with "Danish beneficial
ownership data integration in progress; coverage in v1.1." — the flag is
never silent.

**No `evidence_tier` field or "Evidence Tier 1/2/3" label was found
anywhere in code, manifests, or `docs/company/claims.yaml`.** A grep for
`evidence_tier` across `apps/api/src`, `manifests/`, and
`docs/company/claims.yaml` returns no matches. The Tier 1/2/3 structure
this row locks is implemented field-by-field in the executors (Identity
fields, `legal_representatives`, `ubo_availability`) without a formal
tier label or an enforced `insufficient_evidence` gate tied to the exact
Tier 1 field list this row specifies; whether that gate exists was not
traced further for this record.

**DEC-20260812-A retired the Counterparty Assurance framing this contract
was written for.** The product page section structure this row cites
(Entity / Sanctions / Ownership / Bank / Decision-readiness) is not the
current KYB Essentials / KYB Complete / Invoice Verify solution family
CLAUDE.md's March 2026 solutions section describes; the field-level
discipline (never silent on ownership, explicit availability flags) has
carried forward into the executors even though the product-tier
vocabulary it was written to serve has not.

## Reversal conditions

Reconsider this decision if the Evidence Tier vocabulary is formally
replaced by a different customer-facing contract (for example a schema
built around the KYB Essentials / KYB Complete solution family), or if
Documents are promoted from a deferred v1.1 upsell into a fourth Evidence
Tier. Represent a change of this decision through a new decision rather
than editing this protected record in place.
