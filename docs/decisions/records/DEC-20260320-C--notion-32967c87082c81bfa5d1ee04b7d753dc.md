## Decision

Onboard `au-company-data`, a capability that looks up Australian company
data via the Australian Business Register (ABR).

## Context

The row's stated basis, from its own Rationale: Australia is one of 20
countries in the KYB + Invoice Verify spec (v5). An ABR API GUID was
obtained, and the capability was onboarded through the full Onboarding
Pipeline (`DEC-20260320-B`). The executor uses regex-based XML parsing,
adding no new dependency. Price was set to €0.05, since the system
requires a price greater than zero for a non-free-tier capability. 9 of
10 verification checks passed; the smoke test was blocked by a
pre-existing infrastructure issue the row describes as not AU-specific
(`smoke-test.ts` not calling `autoRegisterCapabilities`). Live fixture
verification was recorded as pending deployment to Railway, where
`ABR_AUTH_GUID` is set.

This historical ID is reused by a second, unrelated Notion row (a hotfix
to auto-register's file filter plus a startup health gate, made the same
day) and was an unresolved registry collision until this batch; the two
rows are resolved together in
`archive/sessions/2026-09-05-decision-collision-resolution-DEC-20260320-C.md`
with distinct source-qualified record keys. This record covers only the
au-company-data onboarding row.

## Rationale

The rationale, as the row states it: Australia's inclusion in the KYB +
Invoice Verify country spec required a company-data source; the ABR API
was free, government-operated, and required no new parsing dependency
beyond regex-based XML handling, at a nominal €0.05 price point.

## Consequences

Status verified on 2026-09-05, against `main`.

**The capability exists and matches the row's description.**
`manifests/au-company-data.yaml` declares `category: company-data`,
`price_cents: 5`, `is_free_tier: false`, `data_source: Australian
Business Register (ABR)`, `data_source_type: api`, matching the row's
€0.05 price and ABR data source. `apps/api/src/capabilities/au-company-data.ts`
implements a regex-based ABN validator (`ABN_RE`) and calls the ABR XML
SOAP endpoint, consistent with the row's "regex-based XML parsing (no
new dependency)" description.

**The env var rename the row's Outcome recorded is reflected in the
executor and the env manifest.** The row's own Outcome field (not
quoted in Decision above, since Decision here restates only the row's
Decision text) records the var was renamed `ABR_AUTH_GUID` →
`ABN_LOOKUP_GUID` to match Railway. `apps/api/src/capabilities/au-company-data.ts`
reads `process.env.ABN_LOOKUP_GUID` exclusively, and
`config/env-manifest.yaml` carries an `ABN_LOOKUP_GUID` row, not
`ABR_AUTH_GUID`. No trace of the old name remains in either file.

This record does not independently verify the row's claimed commit
sequence (`dd7de75`, `90c2eee`, `5919cc9`) or its "9/10 verification
checks" and "11 smoke test steps" figures; those are the row's own
Rationale and Outcome text, preserved as sourced.

## Reversal conditions

None recorded on the row (`Superseded By` is null in the source). A
future decision removing `au-company-data` or replacing its data source
would supersede this row.
