## Decision

Add an 11th rule to the closing-steps checklist for the cc-prompts skill: any
prompt that logs a DEC entry superseding a prior DEC must include a closing
step that sweeps memory and project knowledge for references to the
superseded DEC and replaces them with pointers to the new DEC.

## Context

The row's own Rationale names its trigger directly: "The 2026-05-02–05 drift
(DEC-20260502-A Counterparty rename, DEC-20260503-A dual-domain, DEC-20260503-B
SQS public-score retirement) propagated into Notion Decisions DB on day one
but didn't sync to memory or project knowledge for 2–3 days. Closing-steps
Rule 8 (Decision log) didn't include the propagation sweep." The row states
this is "Direct application of Working rules Rule F (DEC-20260424-A):
always-enforce DECs require structural enforcement, not documentation," so
`affirms DEC-20260424-A` is recorded (that record exists on the PR head).
No other Decision ID is named as changed by this row's own text.

## Rationale

As the row states it: structural enforcement lives in "closing-steps Rule 11
in project knowledge cc-prompts skill (closing-steps-checklist.md)." The
read-back check the row specifies: "chat reviews CC reports for the sweep
step on DEC-superseding prompts; failure to sweep produces a Journal
course-correction entry naming the prompt that bypassed Rule 11."

## Consequences

Status verified on 2026-09-05, against `main`.

**The mechanism this row names (a cc-prompts skill closing-steps-checklist
Rule 11, enforced by a chat read-back of CC reports) is not the mechanism
that exists in this repository today.** `closing-steps-checklist.md` and the
cc-prompts skill are not files in this repo; they belonged to the chat-side
tooling this row's own Rationale describes. The repo-native successor is
structural rather than a checklist rule: `CLAUDE.md`'s Workflow Invariants
section states plainly, "Supersessions → ALWAYS use Contradiction Protocol
(including CLAUDE.md update)," and the M2 closure register
(`docs/project/m2-closure-register.yaml`) is itself the sweep this row asked
for, applied to every historical Decision row rather than only ones a
session happens to touch: each Decision row is classified against the
collision registry, existing formal records, and protocol labels, and a
session cannot silently leave a superseded row unaddressed without the
register's own validation failing. `handoff/README.md` states the same
discipline for handoff notes: "Regenerated by `npm run archive:index`...
Checked in CI by `npm run archive:index -- --check`. Do not edit by hand,"
an automated index rather than a human sweep-and-replace step.

**No evidence in this repository confirms whether the specific 2–3 day sync
gap this row diagnoses (DEC-20260502-A, DEC-20260503-A, DEC-20260503-B) was
ever closed by the mechanism the row proposed.** That gap lived in
chat-memory and project-knowledge artifacts outside this repository's
version control, so this record cannot verify closure of the originating
incident, only that the repo-native successor mechanism (the M2 closure
register plus `Contradiction Protocol`) supersedes the specific proposed
fix in shape.
