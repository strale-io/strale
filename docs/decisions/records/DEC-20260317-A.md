## Decision

Use a weekly digest email (Monday 8 AM CET) plus interrupt emails for
time-sensitive events, rather than a daily email, as the platform health
monitoring model.

## Context

The row's stated basis, from its own Rationale: "At 229 capabilities and
pre-revenue, daily emails are noise. Weekly digest (Monday 8 AM CET)
covers the review cycle. Interrupt emails for time-sensitive events (mass
failure, imminent suspension, billing issues). Can increase to daily if
catalog exceeds 1,000 or interrupt frequency suggests weekly is too
long."

The historical Notion scope field on this row was `global`. It is
recorded here as `scope: technical`: it specifies a monitoring
notification cadence and mechanism, not a company-wide strategic
decision. The row's own text does not name any other Decision ID, so no
relation edge is recorded here.

## Rationale

The rationale, as the row states it: at pre-revenue scale, daily emails
would be noise the founder tunes out; a weekly cadence with a separate
interrupt channel for genuinely urgent events (mass failure, imminent
suspension, billing issues) matches the actual review cycle, with an
explicit threshold (catalog past 1,000 capabilities, or interrupt
frequency itself suggesting weekly is too slow) for revisiting the
cadence.

## Consequences

Status verified on 2026-09-05, against `main`.

**Both halves of the model exist in code, under different names than the
job the row implies, and the interrupt half is unwired.**
`apps/api/src/lib/digest-sender.ts` states directly in its own header
comment: "Send the weekly digest (or any platform health email) via
Resend." `apps/api/src/routes/internal-health-monitor.ts` exposes `POST
/v1/internal/health-sweep` ("Trigger the weekly health sweep on-demand")
and `POST /v1/internal/health-monitor/send-digest` ("Compile and send
the weekly health digest immediately"), both calling `sendDigestEmail`
from `digest-sender.ts`. Separately, `apps/api/src/lib/interrupt-sender.ts`
exists, with its own header comment: "Sends time-sensitive interrupt
emails for events that can't wait for the weekly digest. Expected
frequency: 0-2 per week in normal operation," the exact model the row
describes. But its exported function, `sendInterruptEmail`, has zero
callers anywhere in `apps/api/src` (`grep -rn "sendInterruptEmail"
apps/api/src --include=*.ts` matches only its own definition file); it is
built but never invoked. The interrupt path that is actually wired today
runs through a different module, `apps/api/src/lib/intelligent-alerts.ts`,
which imports `sendDigestEmail` from `digest-sender.ts` directly (not
`interrupt-sender.ts`) to send its own alert emails.

**The job literally named `daily-digest.ts` is a distinct, separate
artifact from the "weekly digest" the row describes, and it rotted.** A
later, unmigrated row, DEC-20260511-F (`Status: active`, prose only, not
a formal record and not part of this batch), states: "The daily-digest
pipeline (apps/api/src/jobs/daily-digest.ts -> Resend -> petter@strale.io)
has not produced a successful run since 2026-04-14. digest_snapshots
table is empty for 27 days; Petter confirmed no digest emails received
in that window." No cron trigger or scheduled workflow for
`daily-digest.ts` was found in this repository
(`find .github/workflows -iname "*.yml" | xargs grep -ln "digest"`
returns nothing); its invocation, if any, happens outside version
control.

**DEC-20260822-A's daily-run reform replaced the monitoring artifact
entirely, on a daily cadence, contradicting this row's premise that
daily is noise at this scale.** `docs/company/DAILY-RUN.md`, authoritative
since 2026-08-22 per DEC-20260822-A, describes a "CEO morning brief"
written after every daily operating session, a structurally different
artifact (business synthesis, not a technical digest) running at a
cadence this row explicitly argued against. This record cannot say
whether the weekly-cadence reasoning in this row was ever revisited
before DEC-20260822-A moved to daily; only that the platform's monitoring
artifact today is daily, not weekly, and is a different pipeline
(the CEO brief process, not `daily-digest.ts` or `digest-sender.ts`).

## Reversal conditions

None recorded on the row (`Superseded By` and `Outcome` are both null).
DEC-20260511-F documents the digest pipeline's silent failure; DEC-20260822-A
introduced the daily CEO-brief artifact that functions as today's
monitoring cadence. Neither is a formal supersession of this row's
weekly-plus-interrupt model, so this record states the current state as
a contradiction rather than a resolved reversal.
