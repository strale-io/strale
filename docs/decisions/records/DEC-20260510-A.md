## Decision

Adopt a promote-and-clean policy for `handoff/_general/from-code/`: at the
next inventory pass, promote genuinely useful untracked session-handoff
notes to tracked files and discard pure session-progress narration; keep
this as soft, session-end discipline rather than a structural
(`.gitignore`) enforcement, with an explicit escalation trigger if untracked
notes keep accumulating.

## Context

The row's own Rationale states the trigger: "Trunk's
handoff/_general/from-code/ accumulated 8 untracked .md files over ~5 days
(chat session 2026-05-10 inventory). These were CC's templated
session-handoff notes — Intent: header, mostly with 'Non-obvious learnings'
sections — that the operator never git add-ed. Inventory classification: 5
PROMOTE-TO-TRACKED (runbooks, decision rationale, registry-build learnings),
3 DISCARD (pure session-progress narration superseded by what shipped), 0
KEEP-AS-DRAFT. PR #83 promoted the 5 and removed the 3. Decision:
Promote-and-clean (Option 3 of 4 considered)." The row states the escalation
condition explicitly: "if untracked notes accumulate (>3 unresolved older
than 3 days) at next inventory ~2 weeks out, escalate to Option 2: full
.gitignore + explicit git add -f for promotion." No other Decision ID is
named in the row's own text, so no relation edge is recorded.

## Rationale

As the row states it: "Per Rule F, structural enforcement is a closing-step
in the cc-prompts skill at closing-steps-checklist.md — that follow-up is
filed as a To-do; this DEC is marked active per Rule F's 'name the
enforcement gap as a follow-up' carve-out." The chosen option (soft
discipline, no `.gitignore` change) was deliberate: the row states the
directory "remains an intentional handoff archive with 89+ tracked files."

## Consequences

Status verified on 2026-09-05, against `main`.

**The soft, session-end promote-and-clean discipline this row adopted was
superseded in kind, not by a supersession record, by full automation.**
`handoff/README.md` states plainly: "handoff/ — session handoffs,
auto-generated index... Regenerated by `npm run archive:index` (writes both
this file and `archive/README.md`). Checked in CI by `npm run archive:index
-- --check`. Do not edit by hand." The manual promote-or-discard triage this
row describes (5 promoted, 3 discarded, escalation trigger at >3 unresolved
older than 3 days) has no equivalent left to trigger: the index is
regenerated and CI-checked on every change, so there is no longer a manual
inventory pass at which the >3-unresolved threshold could be evaluated. The
directory this row discusses has grown far past the "89+ tracked files" it
states at the time: `handoff/README.md` currently reports "244 files (217
with a recorded intent, 27 without)," a count that moves with every handoff
this repository records, so this record cites it only as of this
verification rather than as a fixed figure.

**The T15 receipts and migration-ledger discipline is a separate,
stricter successor for the evidentiary content this row's "PROMOTE-TO-TRACKED"
classification cared about (runbooks, decision rationale, registry-build
learnings), not a supersession of this row.** `docs/programs/cto-readiness/PROGRAM.md`
names T15 as "Receipts and migration ledger" with the rule "Test and audit
evidence is an immutable receipt file cited by path, never a count in
prose." That is a stricter, machine-checked discipline than "promote a
useful handoff note to tracked," but it targets test/audit evidence
specifically, not the general handoff-note hygiene problem this row solves;
this record treats it as a related but distinct successor rather than a
formal supersession.

## Reversal conditions

`Superseded By` is null. `Outcome` is null. The row's own Rationale states
the actual escalation trigger: untracked notes accumulating past 3, older
than 3 days, at the next ~2-week inventory; that trigger has no equivalent
mechanism in the current auto-generated-index regime, since there is no
longer a manual inventory pass to fire it.
