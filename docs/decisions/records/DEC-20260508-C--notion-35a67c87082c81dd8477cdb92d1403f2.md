## Decision

Extend the audit-first template at point 1: add a "Files I will modify"
sub-list and a cross-worktree write-conflict check. Halt on a file modified
less than one hour ago in another worktree; warn on a stale modification of
one hour or more.

## Context

The row's Rationale states: "Worktree consolidation (DEC-20260508-B) created the conditions for parallel CC sessions across strale-work, strale-research, and additional worktrees as needed. The most common parallel-session failure mode is mode-1 conflict: another worktree already has the file modified, and CC is about to overwrite, branch from, or otherwise contend with it. Detection at audit phase prevents wasted CC time and merge conflicts that fragment work."

## Rationale

Per the row: "Mode-2 (planned-but-not-yet-touched overlap) and mode-3 (concurrent draft-time overlap) are not covered by this check; if either becomes recurring, layer on CC-side session manifests as a follow-up. The 1-hour mtime threshold is a starting heuristic; tune after observing false-positive rates." The row explicitly scopes the check to one failure
mode (mode-1) and records the two it deliberately leaves uncovered.

## Consequences

This repository does not carry a file literally named an "audit-first template," so this record cannot verify the specific 1-hour mtime threshold
mechanism against a file at HEAD. `CLAUDE.md`'s Session contract and
Shared-Checkout Rule describe the surviving concern this row addressed
(concurrent sessions against the same checkout) but through a different
mechanism: worktree isolation per agent, rather than a pre-write mtime
check inside a per-session audit template. Whether the specific mtime-based
check this row describes still runs today is not verifiable from files in
this repository.

## Reversal conditions

Supersede this decision if the cross-worktree write-conflict check is
replaced by a different detection mechanism (for example, a session
manifest covering modes 2 and 3), or if the per-agent worktree-isolation
rule in `CLAUDE.md` makes this check's failure mode structurally
unreachable.
