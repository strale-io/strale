## Decision

Migrate `swedish-company-data` off scraping Allabolag.se and onto
Bolagsverket's official Vardefulla datamangder (HVD) REST API, in four
phases, PARKED on 2026-04-09 pending revenue: Bolagsverket API pricing
confirmed at 5,000 SEK (approximately EUR 450) setup plus 1,000 SEK/month
(approximately EUR 90) for the 500-transaction tier, with unused
transactions not rolling over. The row records the decision as "remains
active in principle; execution deferred," with an explicit revival
trigger: the first paying Swedish customer, or cumulative Swedish KYB
calls exceeding 100/month on the then-current scraper.

## Context

Four Swedish capabilities scraped Allabolag.se via Browserless at the time
of this row: `swedish-company-data` (recorded SQS 46, approximately 50%
success rate), `annual-report-extract`, `credit-report-summary`, and
`business-license-check-se`. Allabolag is recorded as owned by UC/Enento
Group, described as a direct KYB competitor; the row frames this as a
reliability and legal-exposure problem under the EU Database Directive
96/9/EC, and as a positioning contradiction against Strale's public claim
that its differentiator is government registries and licensed providers.
The `data_source` DB column already said "Bolagsverket" (seeded in
migration 0011) while the code scraped Allabolag.

Bolagsverket launched a REST API in February 2025, providing registration
data and iXBRL annual reports from 2020 onward at a 20 req/sec rate limit;
per-call pricing was confirmed 2026-04-09.

The row records a four-phase migration, parked pending revenue: Phase 1
(Audit) completed 2026-04-09 (`tasks/2026-04-09-bolagsverket-audit.md` at
the time; the file now lives at
`archive/sessions/tasks/2026-04-09-bolagsverket-audit.md`, moved there by
the 2026-08-17 archive sweep CLAUDE.md's Report Filing Convention records);
Phase 2, migrating
`swedish-company-data` and `business-license-check-se` onto the direct
Bolagsverket API; Phase 3, rebuilding `annual-report-extract` on iXBRL;
Phase 4, a separate decision on `credit-report-summary` (`DEC-20260405-B`,
no formal record exists for that id on `main` and it is not in
`docs/decisions/id-collisions.yaml`, so it is mentioned here in prose
only).

The row also records a structural gate as remaining active regardless of
the parked Sweden migration: "No new capability may be built on a
commercial aggregator when a government API or official open data source
exists for the same jurisdiction." It names as related:
`DEC-20260225-P-m5n6` (the original Allabolag choice; no record exists,
mentioned in prose only) and `DEC-20260320-B` (the Capability Onboarding
Pipeline, a formal record on `main`).

The historical Notion scope field on this row was `global` in the
workspace's old vocabulary. It is recorded here as `scope: technical`
under this repository's decision-record vocabulary: this is a data-source
migration choice for one capability family.

## Rationale

The rationale is cost-versus-revenue sequencing: the Bolagsverket API's
fixed setup and monthly commitment is not justified while Swedish revenue
is zero, so the row commits to the migration in principle while deferring
its execution until a named revenue or volume trigger fires.

## Consequences

Status verified on 2026-09-04, against `main`.

**The migration this row parked was completed, not deferred.**
`apps/api/src/capabilities/swedish-company-data.ts` fetches Bolagsverket's
Vardefulla datamangder API directly (`https://gw.api.bolagsverket.se/vardefulla-datamangder/v1`,
OAuth2 token exchange against `https://portal.api.bolagsverket.se/oauth2/token`
using `BOLAGSVERKET_CLIENT_ID`/`BOLAGSVERKET_CLIENT_SECRET`), with a code
comment reading "DEC-20260405-A Phase 2: replaced Allabolag scraping with
direct Bolagsverket API." `manifests/swedish-company-data.yaml` states
`data_source: Bolagsverket Vardefulla datamangder API (Swedish Companies
Registration Office, EU Open Data Directive HVD)`. The migration commit is
`cb787ed9`, dated 2026-04-22 on `main`
(`https://github.com/strale-io/strale/commit/cb787ed9b2fbfadf61ea401c29d1fd47ac4e9214`),
thirteen days after this row's own "PARKED 2026-04-09" note and before
this row's stated revival trigger (a paying Swedish customer, or
Swedish KYB volume exceeding 100/month) is independently verified here as
having fired. The row's Decision text records Phase 2 as deferred pending
revenue; the code and commit history show Phase 2 executed regardless.
This record keeps the row's Decision text unedited and states the
discrepancy here, in Consequences, without resolving why the deferral did
not hold. `config/env-manifest.yaml` carries `BOLAGSVERKET_CLIENT_ID` and
`BOLAGSVERKET_CLIENT_SECRET` rows (`holder: petter`, `cost_class: free`,
`required_in: [production, local]`), each flagged with a `cost_note`
stating the cost tier was not independently re-verified in the session
that wrote it, flagged for confirmation rather than assumed free with
confidence, so today's actual per-call cost against
this row's confirmed SEK figures is not independently re-verified by this
batch either.
