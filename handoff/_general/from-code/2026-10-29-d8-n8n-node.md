# Built

`packages/n8n-nodes-strale` (source moves into the monorepo; 0.1.x came from `strale-io/n8n-nodes-strale`):

- Three fixed operations ported from the Zapier jobs (`packages/zapier-strale/lib/jobs.js`): Company → Look Up (GB, SE, NO, FI), VAT Number → Check, Person → Screen Name (sanctions, then PEP). Company status and invoice issuer are left out because their tools still answer 404 publicly, as in Zapier.
- API-key credential tested on `GET /v1/wallet/balance`. Requests carry `X-Strale-Client: n8n-nodes-strale/1.0.0` and `?src=n8n`. Each check is capped at 100 cents.
- Billing safety: pending checks are polled by transaction ID and never resubmitted; a billed POST needs a 30 s budget inside a 90 s item deadline; every failure after a billed check names the submitted transaction IDs, including Continue On Fail output.
- No runtime dependencies, no env or file access. Lint uses n8n's own rules (the `n8n-node lint` config with the scanner's plugin versions). `@n8n/node-cli` and `n8n-workflow` ≥ 2.12 were dropped as dev dependencies because they pull `isolated-vm`, a native addon that does not build on the repo's Node 20 CI; tests pin `n8n-workflow` 2.11.1.
- Tests drive the compiled node through n8n-workflow's `NodeHelpers` and error classes, check parity with the Zapier jobs, and validate the three example workflows. `check-framework-packages.mjs` has a rule for this package with a planted-failure test.
- Templates: look up a company, check a VAT number, and a monthly VAT re-check over a supplier sheet. No sanctions re-screening template and no finance or compliance targeting (DEC-20261027-B item 8). Categories Utility and Productivity.
