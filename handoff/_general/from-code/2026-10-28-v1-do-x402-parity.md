## Findings resolved

1. **Claim/replay.** `executeFreeTier` uses `claimX402Payment` after verification
   and input gates, before execution. The claim is the transaction row; no second
   row is inserted for the same request. The gateway's cached-row lookup moved
   into `x402-payment-claims.ts` and also selects the fields needed for the
   `/v1/do` envelope. Completed hashes return cached results; in-progress/failed
   hashes and exhausted budgets return 502 with `error_code: payment_failed`,
   `meta.replayed: true`, `details.retryable: false`, and the gateway's advice to
   check the prior transaction before signing a fresh authorization.
   `beginX402Execution` runs before **every** executor invocation, including a
   transient retry. The existing durable maximum of two executions is shared
   across routes and requests. `finally` calls `releaseX402Claim` with the same
   ownership and execution-started rules as the gateway. Claims retain
   `payment_method=x402`; the existing stale janitor therefore covers them.
   The claim helper takes an optional receipt rail, defaulting to `x402` for
   unchanged gateway behavior and using `v1_do` here. No table change is needed.
2. **Ambiguous settlement.** Both rails now use one settlement policy. The
   `v1_do`/`gateway` discriminator and direct-intent branch were removed.
   `openClaimedX402Intent` fences ownership before settlement. Unknown results
   and thrown facilitator calls retain the executing claim and settling intent;
   confirmed declines release the hash under the existing gateway rules.
3. **Terminal write after settlement.** The gateway's orphan capture was moved
   verbatim into `lib/x402-recording.ts` and reused here. Failed finalization
   returns the successful paid output, preserves the recoverable intent/claim,
   and emits `x402-transaction-recording-failed` plus
   `x402-orphan-settlement-recorded`. If orphan insertion also fails, it emits
   `x402-orphan-settlement-write-also-failed`. The helper masks never-persisted
   input fields. No failed transaction overwrite or capability-health failure
   is recorded for this storage failure. Zero-row claim finalization is also
   treated as a recording failure.
4. **Mark-recorded after settlement.** A separate best-effort catch emits
   `x402-intent-mark-recorded-failed`, retains the completed transaction and
   successful response, and leaves reconciliation to discharge the intent.
5. **Paid metadata.** A settlement with an ID returns the catalogue price and
   `free_tier: false`; the completed row stores that price,
   `paymentMethod: x402`, and `isFreeTier: false`. Verified x402 successes omit
   free-tier upgrade/unlock text. Free-tier and progressive-unlock calls retain
   their behavior, and authenticated wallet/idempotency code is untouched.

All five adjacent `H7b-FINDING` comments were removed. No finding remains open.

## Exact wire and snapshot changes

Only the 11 `/v1/do` characterization snapshots changed. All 22 gateway snapshot
entries are byte-identical to `origin/main`, including their response headers,
writes, event ordering and log names.

- Settled successes: `result.price_cents` changes from `0` to catalogue cents
  (`5` in the fixture); `free_tier` changes from `true` to `false`; `upgrade`
  is omitted. The other result fields and `meta.audit` retain their shapes.
  Paid requests no longer receive or create progressive-unlock messaging.
- Post-settlement transaction-write and mark-recorded failures: HTTP 500 with
  `error_code`, `message`, `details`, `free_tier` and `upgrade` becomes HTTP 200
  with the normal paid `result`, `meta.audit` and `free_tier: false` envelope.
- Completed replay: HTTP 500 becomes HTTP 200 with the original
  `result.transaction_id`, `status`, `capability_used`, `price_cents`,
  `latency_ms`, `output`, `provenance`, and stored `meta.audit`;
  `meta.replayed: true` is added. Stored audit error strings pass through the
  existing `redactAuditTrail` helper, as other stored-audit response paths do;
  stored bytes are not rewritten. No execution or settlement occurs.
- In-progress/failed/budget-exhausted replays newly return HTTP 502 with the
  `/v1/do` error envelope described above; this is covered by explicit tests.
- Confirmed decline and unknown settlement retain their HTTP 402 envelope.
  Thrown-facilitator and pre-settlement execution failures retain their existing
  HTTP 500 envelope. Their claim/intent persistence changes are captured in the
  snapshots. `valid: true` without a settlement ID retains its legacy zero-price,
  `free_tier: true` response and failed intent, but omits the upgrade block on
  the verified-x402 success path. No settlement-ID validation was added.
- No new payment-response header is introduced. The gateway's headers remain
  unchanged. Claim counters/hash/receipt metadata and pending/deferred integrity
  state are internal snapshot changes, not added wire fields.
