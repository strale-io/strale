### 1c. Structural context — the October 2025 law change

A Polish law amendment (in force October 2025) formally codified two tiers:
- **Open API** (public, everyone, free): anonymized JSON as already described
- **Full API** (restricted): complete data including officer names and PESEL numbers, available **only to entities that receive a ministerial decision (decyzja ministra)**. Eligible entities are limited to public bodies and "entities performing public tasks" authorized to examine financial activities to prevent economic crime. **Not available to private commercial SaaS companies.** A new criminal penalty of up to 2 years imprisonment applies to unauthorized network-based access to full KRS data.

## Path 2 — Same vendor, authenticated free path

- **KRS Open API authentication model:** the public-facing KRS API (`api-krs.ms.gov.pl`) has **no authentication layer** — it is completely open, no API key, no OAuth. Anyone can call it. The anonymization of officer names is **not unlockable by auth** at the Open API tier.
- **What auth-based registration would unlock:** none at the KRS Open API level. The anonymization is structural policy, not a rate-limit-bypass gate.
- **Full API (Minister decision path):** formally requires a positive administrative decision from the Polish Minister of Justice. Only public bodies qualify. Lead time unknown (administrative decision process). Strale is a private SaaS company in Sweden — **structurally ineligible**.
- **MGBI KRS API (`/v1/models/pl-krs-wp-record/records`):** a third-party API wrapper that returns KRS PDF URLs. Requires authorization key from MGBI (contact-form registration, no public pricing disclosed). Does return PDF URLs from which full names can be extracted — but this is a paid third-party service (Path 4 territory), not a "free authenticated path."
- **Verdict: NOT VIABLE.** There is no free authenticated path that unlocks non-anonymized JSON officer data. The Full API tier is structurally closed to Strale.

- **URL structure confirmed:** `https://wyszukiwarka-msig.ms.gov.pl/api/Monitor/Download?id=7551&fileId=true` returns a downloadable PDF issue (~2MB). Issues are individually downloadable.

## Path 6 — Public web UI HTML/PDF

### 6a. The web UI (`wyszukiwarka-krs.ms.gov.pl`)

- **URL structure:** Searches available at `https://wyszukiwarka-krs.ms.gov.pl/`. Detail pages use encrypted KRS numbers: `https://wyszukiwarka-krs.ms.gov.pl/dane-szczegolowe-podmiotu;numerKRS={ENCRYPTED};typ=P` — the KRS number is AES-128-CBC encrypted before use in the URL.
- **No login required:** confirmed by gov.pl official page — "Searching entities in the National Court Register does not require having an account in the system."
- **Legal basis:** The KRS Act (Ustawa o KRS) states the register is a public register open to all. "Everyone can search for an entity in the KRS and obtain information corresponding to a current extract or full extract."
- **What's publicly visible in the web UI:** officer names in FULL (not anonymized) — the web UI shows actual names in Zarząd, Rada Nadzorcza, and Prokurenci sections. Multiple third-party sources confirm this is where full names come from (the PDF download from this UI also has full names).

### 6b. Security mechanics — why the PDF endpoint returns HTTP 400 externally

Developer reverse-engineering (documented publicly) reveals:
1. **AES-128-CBC encryption:** the portal encrypts the KRS number using a hardcoded key `TopSecretApiKey1` (also serves as IV) before embedding it in API calls and URLs
2. **Token steganography:** a 512-character token embeds the encrypted KRS number at specific array positions with checksums and circular shifting — sent as an API parameter to authenticate the PDF download request
3. The PDF endpoint (`/api/krs/OdpisAktualny/{krs}?format=pdf`) returns HTTP 400 without this token, which can only be generated by reverse-engineering the web UI session

This means: the "public" PDF with full names is formally accessible (no auth gate in legal terms) but technically requires browser-session mechanics that no clean external API call can reproduce without mimicking the browser's JS execution.

### 6c. ToS / automated access policy

- **gov.pl KRS page:** "No login required. Anyone can search." No explicit prohibition on automated access found in the available page text (Creative Commons CC BY-SA 4.0 for website text; data policy references data processing policies).
- **Statutory basis:** The KRS Act is explicit that the register is public and accessible to all. The data is "publicly accessible" in the legal sense.
- **No robots.txt reference or explicit ToS prohibition captured** from the available content, though such restrictions may exist elsewhere.

### 6d. DEC-20260518-F 4-constraint check

| Constraint | Assessment |
|------------|-----------|
| (1) Statutorily public | YES. KRS Act explicitly mandates public access. |
| (2) ToS permits per-call automated retrieval | UNCLEAR. No explicit prohibition found, but the encrypted-token mechanism suggests the Ministry did not design for external automated retrieval. The October 2025 criminal penalty provision (up to 2 years for unauthorized KRS network access) creates legal risk for any circumvention of the session-token mechanism. |
| (3) Per-entity per-request | YES. Each call returns a single entity's data. |
| (4) Attribution preserved | YES. KRS extract includes provenance (Ministerstwo Sprawiedliwości, register number, date of issue). |

**Constraint (2) is the blocker:** The encrypted session-token mechanism is a technical barrier that the Ministry of Justice deliberately implemented. Circumventing it (even to access publicly available data) now carries criminal exposure under the October 2025 amendment. **DEC-20260518-F's 4-constraint exemption does NOT clearly pass on constraint (2).**

### 6e. DEC-20260428-A Tier 1 status

**BLOCKED.** Strale cannot operate a scraper/automated retrieval against `wyszukiwarka-krs.ms.gov.pl` for three compounding reasons:
1. DEC-20260428-A Tier 1 is absolute — Strale never operates scrapers
2. The encrypted-token mechanics mean any automated access requires reverse-engineering a deliberate security barrier
3. The October 2025 criminal penalty provision for unauthorized network-based KRS access creates legal risk

A **Tier-2 vendor** that has licensed access to the KRS data via a bilateral agreement with the Ministry of Justice (not via the web UI scraping) would be the correct path. Transparent Data, MGBI, and Kyckr all claim to source from KRS officially and return non-anonymized names — the key due-diligence question is whether their access is via a bilateral data agreement or via the web UI session-token trick.

**Verdict: BLOCKED for Strale directly. Tier-2 vendor required with explicit attestation of lawful data sourcing method.**

Even if PL propagates officer data through BRIS, there is no way to query it programmatically without a bilateral BRIS gateway connection (available only to Member State registers, not private companies). Future potential as BRIS reforms implement — watch Directive 2025/25 implementation timeline.

### 8a. Monitor Sądowy i Gospodarczy (MSiG) — Polish official commercial gazette

- **Official portal:** `https://wyszukiwarka-msig.ms.gov.pl/` (redirected from `ems.ms.gov.pl/msig/`)
- **Content confirmed:** Court and commercial announcements including (historically) KRS registration notices, bankruptcy, restructuring, creditor calls, liquidation. Issues downloadable as PDFs at `https://wyszukiwarka-msig.ms.gov.pl/api/Monitor/Download?id={ID}&fileId=true`. Issue PDFs are ~2MB each.
- **October 2025 reform impact:** the KRS amendment removed the requirement to publish KRS entry content in MSiG. **Going forward, officer appointment/resignation changes registered in KRS will NOT appear in MSiG**. This eliminates MSiG as a current officer-data source for newly registered changes.
- **Historical coverage (2001–late 2025):** searchable and downloadable. Contains officer appointment records from first registrations and changes during this period. Useful for historical officer history / tenure reconstruction.
- **Searchability:** web search by entity name, KRS, NIP, case type, date range. No structured export/bulk API from the official portal.
- **Third-party services (iMSiG.pl, MGBI MSiG API):**
  - `imsig.pl`: Web portal + API for MSiG data. API uses API key auth (UUID format). Subscription-based (subscriptions pre-2023 required; bankruptcy list as separate product). Documents/data primarily focused on bankruptcy/restructuring — the officer-appointment KRS entries are secondary content.
  - `mgbi.pl` MSiG API: returns MSiG announcements as JSON from January 2001. RFQ pricing. KRS entry announcements are included.
- **License:** official gazette content, public domain by statute.
- **DEC-20260428-A scope:** building a Strale-operated dataset from MSiG PDFs would be Tier 1 (Strale building on statutory public-domain content) — permitted under doctrine. However, this is a substantial engineering project (PDF OCR, entity resolution, announcement parsing) and the forward-looking value has been reduced by the October 2025 reform removing new KRS entries from MSiG.

### 8b. Polish Notary Chamber (KRN) / KIDP

- Polish notaries handle signing of corporate documents (articles, resolutions, appointments). KRN does not publish a searchable index of notarial acts. Each notary maintains their own archive. **NOT a viable source.**
- KIDP (tax advisor chamber) — out of scope for officer data.

### 8c. KRS filings repository (eKRS)

- All filings made since July 2021 are electronic and stored in the "Repository of Registration Files" (`ekrs.ms.gov.pl`). Documents (including the actual appointment resolution, articles of association, etc.) are publicly available as PDFs free of charge.
- **Access:** via the eKRS/S24 portal (`ekrs.ms.gov.pl/s24/`). PDFs are available without authentication.
- **Content:** raw source documents (notarial deeds, shareholder resolutions, etc.) with full names. Not structured data — requires parsing. Each filing is linked to a KRS number.
- **Verdict: VIABLE as a legal-source tracing path (not a structured API).** The actual appointment documents are publicly available PDFs. But extracting officer names from raw notarial deeds is an NLP/OCR project, not a clean data feed.

### 8d. MSiG verdict

**NOT VIABLE for current officer data** (reform abolished KRS-entry MSiG publication from late 2025). **Viable as historical officer audit trail (2001–2025) via third-party MGBI MSiG API or iMSiG.pl API**, but this is engineering-heavy and covers only historical periods.

### Truly blocked?

**NO.** The earlier KRS "blocked" classification was based on the JSON anonymization of the public API. The PDF tier of the same API contains full names (though the PDF endpoint is technically protected by session tokens). Multiple commercial vendors demonstrably deliver non-anonymized PL officer data via API. At least 3 viable vendor paths exist (Kyckr, Kompany, Transparent Data). None has been confirmed as both (a) per-call/no-platform-fee AND (b) Tier-2 compliant under DEC-20260428-A — hence the v1.1 classification pending RFQ + vendor attestation — but the data clearly exists and is commercially available.

### DEC-20260428-A scope question for Petter

> Poland's KRS web UI (`wyszukiwarka-krs.ms.gov.pl`) displays officer names in full without authentication, and the KRS Act grants public access to this data. However: (1) the PDF download is technically protected by AES-128-CBC session tokens that require reverse-engineering, creating potential legal exposure under the October 2025 criminal-penalty amendment; (2) Strale cannot operate any automated retrieval (Tier 1 absolute). The question is: do commercial vendors like Kyckr, Transparent Data, and Kompany source their non-anonymized PL officer data via (a) a bilateral data agreement with the Ministry of Justice / Full API access (unlikely — Full API is formally restricted to public bodies), (b) PDF extraction from the web UI (most likely, and the encrypted-token mechanism suggests the Ministry did not intend for external automation), or (c) some other licensed arrangement? Strale must require explicit written attestation from the chosen vendor confirming their data sourcing method is lawful, that they hold redistribution rights for the officer data, and that they provide per-record primary-source provenance (KRS number + issue date). Without this attestation, consuming this data carries DEC-20260428-A Tier-2 compliance risk.

### Key finding unique to PL vs other countries

The October 2025 Polish law amendment creates a new structural dynamic: (1) a formal two-tier API (anonymized-public vs full-ministerial) that definitively closes the direct official path for Strale; (2) a criminal penalty provision for unauthorized KRS network access that may create legal risk for vendors who source via web-UI scraping and redistributing; (3) simultaneous abolition of MSiG KRS-entry publication, eliminating an alternate structured gazette path for new officer changes. This combination makes **vendor due-diligence on sourcing method** more critical for PL than for any other EU country analyzed in this audit series.
