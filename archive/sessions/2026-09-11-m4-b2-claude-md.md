## What changed from the patch as written

The patch (`b2_claude_md.patch`) applied cleanly to `CLAUDE.md` and the
`CAPABILITY_ONBOARDING.md` mirror via `git apply --3way`; one unrelated
conflict in `archive/README.md`'s generated index block (a "newest file"
date line, stale relative to `origin/m4/cutover`'s later commits) was
resolved by taking the current branch's line, which a subsequent
`npm run archive:index` regenerated identically. Three pointer changes
were made on top of the patch's `CLAUDE.md` text, per this follow-up
brief's items 1 and 2, because `docs/decisions/records/` and
`docs/decisions/README.md` are still-inactive candidates (frontmatter
`status != active` or `authority_active != true`) that
`checkPrecutoverEntrypoint` fires `M1_ENTRYPOINT_ACTIVATED` on:

1. **Active Decisions section (was line 245).** "Settled decisions are
   records under `docs/decisions/records/`, indexed by the generated
   `docs/project/DECISIONS.md`." became "Settled decisions are indexed by
   the generated `docs/project/DECISIONS.md`, which links to the
   underlying record file behind each entry." The directory reference is
   gone; the reader still learns that a settled decision lives in a record
   file, because the index that replaces the directory pointer links to
   one per row.
2. **Full Session Checklist, item 10 (was line 577).** "Record a decision
   made this session as a new file under `docs/decisions/records/`"
   became "Record a decision made this session as a new decision record,
   following the format of the entries listed in
   `docs/project/DECISIONS.md`". A literal glob such as
   `docs/decisions/records/DEC-*.md` was avoided deliberately: the
   checker treats any token containing `*` as an unverifiable glob and
   fires regardless of activation state, so the fix could not simply spell
   out the naming pattern.
3. **Workflow Invariants (was line 637).** The protected-sections
   sentence's trailing citation, "per `docs/decisions/README.md`", was
   dropped rather than kept, because that file's own frontmatter is
   `status: candidate`, `authority_active: false`, and it is a single-file
   reference, not a directory, so no active substitute exists to point at
   instead. The substantive rule text (five protected sections, never
   edited in place, change is a new record with an explicit relationship)
   is unchanged.

All other `docs/project/*` tokens in `CLAUDE.md` (`START-HERE.md`,
`PROTOCOL-ROUTER.md`, `PRODUCT.md`, `STATE.md`, `ROADMAP.md`,
`DECISIONS.md`) were already active on `origin/m4/cutover` (activated by
`cca7a5a7`, already merged into the integration branch before this batch
started), so those references needed no change. `docs/project/STRUCTURE.md`,
`WORKING-MODEL.md`, `docs/decisions/README.md` as a directory,
`PENDING.md`, and `docs/project/candidates/` do not appear anywhere in the
patch's `CLAUDE.md` text, so there was nothing to repoint for them.
`docs/project/protocol-coverage.yaml`'s three touched `excluded_sections`
reasons (Project Spec, Quick/Full Session Checklist, Workflow Invariants,
Degraded Mode) were updated in the same commit to describe what actually
changed, including correcting one reason's own draft wording that had
claimed the protected-sections rule was restated against
`docs/decisions/README.md` instead of Notion; it was not restated against
that file, it was dropped, for the reason in item 3 above.
