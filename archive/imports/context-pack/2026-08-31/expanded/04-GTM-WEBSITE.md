# Strale — GTM, Revenue, Website and Brand

# Part I — GTM and Revenue

## Goal

Target:
> **$2,000/week**

This superseded the initial $2,000/month target.

The commercial problem is not simply “grow traffic”.

It is:
> How do we create multiple recurring machine-paid buyer habits around Strale?

## What early revenue taught us

The dominant historical buyer/agent demonstrated the core thesis:
- one agent;
- many jobs;
- repeated calls;
- broad capability use;
- machine-compatible buying.

The initial use-case cluster looked like:
- search/SEO;
- commercial research;
- company enrichment;
- prospect/contact work;
- email validation.

That remains useful ICP evidence.

## Distribution diagnosis

A major finding from the revenue work:

Strale was not merely absent from marketplaces/directories. It was often:
- present but stale;
- weakly described;
- positioned generically;
- not optimized for machine retrieval by job/task.

Therefore higher-value distribution work includes:
- marketplace metadata correction;
- task/job-oriented machine-readable capability descriptions;
- understanding x402/Coinbase Bazaar ranking/discovery;
- task-specific Agent Skills/integration assets;
- improving capability discovery itself;
- identifying developers/operators whose agents repeatedly need Strale’s capability mix.

Do not default to broad low-quality directory submission.

## Commercial evidence discipline

### Complete windows
Never draw concentration/acquisition conclusions from a partial week.

### Buyer identity
Wallet count ≠ buyer count.

Separate:
- meaningful buyers;
- tiny/dust wallets;
- internal/test;
- linked identities where evidence supports it.

### Repeat behavior
A buyer returning on another day matters more than many tiny one-off calls.

### Entry capability
Track the first meaningful capability a new buyer uses.

Recent evidence:
- card buyer returned through `competitor-compare`;
- new meaningful buyers entered through `address-geocode` and `image-to-text`.

This weakens the assumption that growth must come first from KYB/compliance.

## Current commercial interpretation

The business is no longer accurately described as literally one customer.

Concentration remains high, but:
- it has improved across comparable complete windows;
- multiple real buyers exist;
- non-largest buyers have begun repeating;
- the largest buyer did not need to disappear for diversification to begin.

This is promising evidence, not PMF.

## Customer-contact constraint

A specific card-paying customer was discussed.

Founder decision:
> **Do not reach out to that buyer.**

Do not repeatedly reopen this matter.

## Bundle/cohort experiment

A specific cohort/bundle demand experiment failed:
- cohort orders: zero;
- control continued selling;
- listing/price confounds were checked.

Implication:
- that specific demand hypothesis failed;
- do not keep privileging it after contrary evidence.

## Near-term GTM program

1. Improve machine discovery/retrieval.
2. Improve x402 catalogue metadata.
3. Maintain high-quality schemas/contracts.
4. Correct marketplace positioning where stale.
5. Build task-specific integration instructions/skills.
6. Track new meaningful buyer entry capabilities.
7. Track repeat buyers separately from wallets.
8. Build new capabilities from demonstrated demand gaps.
9. Complete the website so human builders understand Strale quickly.
10. Avoid broad outbound until product/distribution mechanics warrant it.

## Metrics that matter

Primary:
- weekly external revenue;
- meaningful real buyers;
- top-buyer share on comparable complete windows;
- non-top repeat buyers;
- revenue excluding largest buyer;
- new meaningful buyer count;
- spend/calls per meaningful buyer.

Product/distribution:
- discovery success;
- repeat capability use;
- first capability used by new buyer;
- failed/poor-match discovery queries;
- x402 catalogue consumption;
- MCP/API adoption.

# Part II — Website and Brand

## Website objective

Explain Strale to:
- human builders evaluating the platform;
- agent developers who need concrete product proof.

Do not make the homepage feel like:
- generic AI SaaS;
- a card-grid catalogue;
- a crypto landing page;
- API documentation pasted into marketing.

Core message:
> **One connection to the tools your agent needs.**

## Canonical homepage sequence

1. Header
2. Hero
3. How Strale Works
4. Featured Tools
5. Use Cases
6. Developers + x402
7. Reliability
8. Pricing / Access
9. Closing CTA
10. Footer

Keep this order unless a concrete product/design conflict emerges.

## Brand direction — Quiet Material

### Typography
- Instrument Sans
- IBM Plex Mono for technical labels

### Surfaces
- white
- pearl
- mineral neutrals

### Accent family
- oxide red
- cobalt/navy
- mineral green

### Atmosphere
- folded material
- soft mineral fields
- restrained gradients

### UI treatment
- glass used sparingly, mainly navigation/overlays
- selective rounding
- selective shadows
- avoid “everything is a floating card”

## Hero

Current:
- eyebrow `TOOLS FOR AI AGENTS`
- headline `One connection to the tools your agent needs.`
- technical line `HTTP API · MCP · PAY PER SUCCESSFUL CALL`
- atmospheric folded-material stage
- animated request/result proof:
  - Google Search
  - Swedish Company Data
  - Email Validation

Latest direction:
- keep hero;
- replace “Listening” with “Received” / “Request” or another accurate state;
- slow enough for results to be read;
- reduce dead space in routing states.

## How Strale Works

Sequence:
1. Connect
2. Discover
3. Call
4. Return

Keep interaction model:
- sticky scroll progression;
- clickable tabs;
- keyboard accessibility;
- reduced-motion behavior.

Current weakness:
- generated marketing illustrations are attractive but generic;
- they explain too little;
- they diverge from the stronger hero language.

Latest direction:
- stop treating “better AI illustrations” as the answer;
- prototype code-native visuals.

Desired grammar:

### Connect
Agent → HTTP/MCP → Strale

### Discover
Task → matching capabilities → one selected

### Call
Agent → Strale → selected capability/provider execution

### Return
One structured result with source/provenance/execution context

Folded material should become atmosphere behind the mechanism.

## Batch A refinements before freeze
- reduce oversized whitespace before the stepper;
- reduce panel height ~10–15% or increase content density;
- increase right-side visual prominence;
- test less component-like active-step treatment;
- refine Call copy (`Strale handles the call` is a stronger direction than `Call the tool through Strale`).

## Remaining sections

### Featured Tools
Avoid another generic card grid.
Prefer dense editorial/list/catalogue treatment.

### Use Cases
Narrative task stories:
- research a company
- enrich a lead
- verify an email
- compare competitors
- inspect a document

### Developers + x402
Show concrete technical proof:
- HTTP API
- MCP
- x402 authorization/payment
- structured output

### Reliability
Use evidence:
- execution states
- provenance
- failure/no-charge semantics
- receipts where claims are accurate

Do not claim customer-facing signed receipts yet.

### Pricing / Access
Keep simple:
- pay per successful call
- prepaid/API access where relevant
- x402

## Risks to avoid
- too much blue
- bright synthetic AI gradients
- excessive glass
- excessive pills
- nested cards
- card grids everywhere
- meaningless generated abstract art
- crypto visual tropes
- overly literal icons

## Domain

Owned:
- `strale.dev`
- `strale.io`

Website/rebrand work leaned toward `strale.io` as broader brand domain, but confirm before irreversible infrastructure changes.
